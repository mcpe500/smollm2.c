# Weight Shape Verification: HF Safetensors vs .sm2 Format

**Date:** 2026-05-28
**Status:** VERIFIED CORRECT

## Summary

Weight shapes between HuggingFace Safetensors and our .sm2 format are **identical**. The conversion script does NOT transpose any weights - it writes them exactly as stored in safetensors.

## Safetensors (HuggingFace) Shapes

For SmolLM2-135M-Instruct:
- `model.embed_tokens.weight`: **[49152, 576]** (vocab_size, dim)
- `model.norm.weight`: **[576]** (dim)
- `q_proj.weight`: **[576, 576]** (dim, dim)
- `k_proj.weight`: **[192, 576]** (n_kv_heads * head_dim, dim) = (3*64, 576)
- `v_proj.weight`: **[192, 576]** (n_kv_heads * head_dim, dim)
- `o_proj.weight`: **[576, 576]** (dim, dim)
- `gate_proj.weight`: **[1536, 576]** (hidden_dim, dim)
- `up_proj.weight`: **[1536, 576]** (hidden_dim, dim)
- `down_proj.weight`: **[576, 1536]** (dim, hidden_dim)

## .sm2 File Shapes

Verified by reading header of `smollm2-135m.sm2`:
- `tok_embeddings`: **[49152, 576]** - MATCHES
- All layer weights match safetensors exactly

## C Code Matmul Expectations

The C code (`src/sm2_context.c`) performs matmuls as `x @ W^T`:

### Q/K/V Projections
```c
// q_proj[i] = sum_j xb_out[j] * q_proj[i, j]
// This is: q = xb_out @ q_proj^T
for (int i = 0; i < dim; i++) {
    for (int j = 0; j < dim; j++) {
        sum += xb_out[j] * q_proj[i * dim + j];
    }
}
```

### Embedding to Logits
```c
// logits[i] = sum_j final_h[j] * tok_embeddings[i, j]
// This is: logits = final_h @ tok_embeddings^T
for (int i = 0; i < vocab_size; i++) {
    for (int j = 0; j < dim; j++) {
        logits[i] += final_h[j] * tok_embeddings[i * dim + j];
    }
}
```

## Why This Works

In PyTorch:
- Linear layer stores weights as `[out_features, in_features]`
- `F.linear(x, W)` computes `x @ W^T`
- Safetensors stores PyTorch weights as-is

In our C code:
- Weights stored in same format as PyTorch
- Code explicitly computes `x @ W^T`
- Result: mathematically equivalent to PyTorch

## Conclusion

**No weight transposition issue.** The conversion is correct.

- Safetensors stores: W[out, in] (PyTorch convention)
- Our .sm2 stores: same format
- Our C code computes: x @ W^T

This matches the mathematical operation that PyTorch performs.
