# Attention Mechanism Verification

**Date:** 2026-05-28
**File:** `src/sm2_context.c` lines 128-177
**Model:** SmolLM2-135M (30 layers, dim=576, n_heads=9, n_kv_heads=3, head_dim=64, max_seq=8192)

---

## 1. Implementation Overview

The attention mechanism uses Grouped Query Attention (GQA):
- 9 query heads, 3 KV heads, group_size = 3
- Each KV head serves 3 Q heads via duplication

### 1.1 Cache Indexing Formula

```c
int cache_idx = kv_head * ctx->params.max_context * head_dim + pos * head_dim + d;
```

This maps to flat array layout: `[kv_head][pos][d]` with stride = `max_context * head_dim`.

### 1.2 Attention Flow (GQA)

For each query head `qh`:
1. Map to KV head: `kv_head = qh / group_size` (integer division)
2. Compute dot products Q[qh] · K[kv_head, pos] for all positions
3. Scale by `1/sqrt(head_dim)` = 1/8
4. Softmax with numerical stability (subtract max)
5. Weighted sum of V values

---

## 2. Correctness Analysis

### 2.1 Softmax Normalization: CORRECT

```c
out[qh * head_dim + d] = sum / sum_exp;
```

Divides by `sum_exp` (sum of exp scores), producing proper softmax probabilities.

### 2.2 Score Scaling: CORRECT

```c
dot *= 1.0f / sqrtf((float)head_dim);
```

- head_dim = 64
- 1/sqrt(64) = 1/8 = 0.125
- Standard attention scaling factor

### 2.3 Cache Indexing: CORRECT (formula only)

The formula `kv_head * max_context * head_dim + pos * head_dim + d` is mathematically correct for accessing `[kv_head][pos][d]` in a flat array.

**HOWEVER: BUG #1 below (max_context vs max_seq mismatch)**

## 3. Critical Bugs Found

### BUG #1: scores[2048] Array Overflow (CRITICAL)

**Location:** Line 144
```c
float scores[2048];
```

**Problem:** max_seq = 8192, but scores array only has 2048 elements.

**Impact:**
- Sequences with kv_seq > 2048 will overflow the stack buffer
- Causes undefined behavior, memory corruption

**Fix:** Either:
```c
float scores[8192];  // Match max_seq
```
Or allocate dynamically if stack is constrained.

---

### BUG #2: max_context vs max_seq Mismatch (CRITICAL)

**Location:**
- `src/sm2_context.c` lines 150, 170, 275 (cache indexing)
- `src/smollm2.c` line 129 (parameter override)

**Problem:**
1. KV cache allocated with `max_seq` (sm2_context.c line 48):
   ```c
   size_t kv_per_layer = (size_t)model->n_kv_heads * max_seq * model->head_dim;
   ```
2. `max_context` CORRECTLY set to `max_seq` during context creation (line 68):
   ```c
   ctx->params.max_context = max_seq;  // 8192 ✓
   ```
3. BUT then OVERRIDDEN in smollm2.c line 129:
   ```c
   ctx->params.max_context = args->ctx_size;  // Default 2048! ✗
   ```
4. Cache indexing uses this overridden value:
   ```c
   int cache_idx = kv_head * ctx->params.max_context * head_dim + pos * head_dim + d;
   ```

**Impact:**
- Cache allocated: n_kv_heads × 8192 × 64 = 1,572,864 floats per layer
- Index stride with ctx_size=2048: kv_head × 2048 × 64 = 131,072
- For pos >= 2048: cache_idx exceeds allocated bounds
- **Out-of-bounds memory access** when processing sequences > ctx_size

**Example (135M with 3 KV heads):**
| kv_head | pos | Correct Index | Buggy Index (ctx_size=2048) | Difference |
|---------|-----|---------------|----------------------------|-----------|
| 0 | 0 | 0 | 0 | 0 |
| 0 | 2047 | 131,008 | 131,008 | 0 |
| 0 | 2048 | 131,072 | OUT OF BOUNDS | - |
| 1 | 0 | 524,288 | 131,072 | 393,216 |
| 1 | 100 | 530,368 | 137,152 | 393,216 |
| 2 | 0 | 1,048,576 | 262,144 | 786,432 |

**Impact Analysis:**
- For kv_head=0: Indices match for positions 0-2047 (within ctx_size)
- For kv_head=1: ALL positions read WRONG data (393KB offset!)
- For kv_head=2: ALL positions read WRONG data (786KB offset!)
- Sequences > ctx_size crash or read garbage

**Root cause:** When ctx_size < max_seq, the stride formula uses wrong multiplier, causing KV heads 1+ to access completely wrong cache regions.

**Fix options:**
1. Remove the override in smollm2.c line 129 (recommended):
   ```c
   // Remove: ctx->params.max_context = args->ctx_size;
   ```
2. Or use max_seq directly in cache indexing:
   ```c
   int cache_idx = kv_head * spec->max_seq_len * head_dim + pos * head_dim + d;
   ```
3. Or add validation:
   ```c
   if (args.ctx_size > max_seq) args.ctx_size = max_seq;
   ctx->params.max_context = args.ctx_size;
   ```

### BUG #3: Decode Self-Attention Redundancy (Minor)

**Location:** Lines 134-136, 458

**Problem:** During decode, the current token's K/V are stored BEFORE attention, causing self-attention:

1. Prefill ends: kv_cache_len = N, K/V at positions [0..N-1]
2. Decode step 0:
   - seq_pos = N (NEW position)
   - K/V stored at position N
   - Attention attends over [0..N] (including self at position N)
   - Q computed from last_token's embedding

This means the last prefill token's Q (from decode step 0) attends to:
- Its own K/V at position N-1 (from prefill)
- Its K/V at position N (from decode, identical values)

**Impact:** Minor redundancy, but not incorrect. The self-attention at position N produces the same weighted sum as position N-1, so output is approximately the same. However, this is wasteful.

**Suggested Fix:** Consider only attending over positions [0..kv_cache_len] during decode (exclude current position), or restructure to compute K/V before storing.

## 4. Prefill/Decode Order Analysis

### 4.1 Prefill Order: CORRECT

```c
for (int t = 0; t < n_tokens; t++) {
    // ... compute Q, K, V ...
    layer_forward(..., seq_pos=t);  // Stores K/V at position t, then attention over [0..t]
    ctx->scratch.kv_cache_len = t + 1;
}
```

Token t:
1. Stores K/V at position t
2. Attention attends over [0..t] (includes self)
3. kv_cache_len = t+1

This is correct causal attention where each token attends to itself and all previous tokens.

### 4.2 Decode Order: CORRECT

```c
int seq_pos = ctx->scratch.kv_cache_len;  // Position after all cached tokens
// ... compute Q, K, V ...
layer_forward(..., seq_pos);  // Stores K/V, attention over [0..seq_pos]
ctx->scratch.kv_cache_len = seq_pos + 1;
```

After prefill with N tokens:
1. seq_pos = N (NEW position)
2. K/V stored at position N
3. Attention attends over [0..N] (correct: all previous + self)
4. kv_cache_len = N+1

## 5. Numerical Stability Analysis

### 5.1 Softmax: STABLE

The implementation uses standard numerical stabilization:
```c
float max_score = -1e9f;
for (int pos = 0; pos < kv_seq; pos++) {
    scores[pos] = expf(scores[pos] - max_score);
}
```

This ensures `exp(x - max)` is in range [0, 1], preventing overflow.

### 5.2 Potential Overflow Risk

**Worst case analysis:**
- Assume Q and K values in range [-10, 10] (typical after RMSNorm + projection)
- Dot product: sum of 64 multiplications
- Maximum dot: 64 × 10 × 10 = 6400
- After scaling: 6400 × 0.125 = 800
- exp(800 - 800) = exp(0) = 1 ✓
- But if max_score = 100 and another score = 900: exp(900-100) = exp(800) → OVERFLOW!

**Actual risk:** Unbounded scores CAN overflow exp(). For long sequences with diverse attention patterns, this is possible.

**Mitigation (already partially done):** Subtract max before exp. Still vulnerable to large variance in attention scores.
