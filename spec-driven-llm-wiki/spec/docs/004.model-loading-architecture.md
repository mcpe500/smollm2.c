## Overview

This document provides complete technical documentation of the `.sm2` file format used by the SmolLM2 C implementation. It covers the binary layout, header structure, tokenizer format, and weight loading for all model variants.

| `SM2_VERSION` | `1` | File format version |
| `SM2_KV_PAGE_TOKENS` | `16` | KV cache page granularity |

### Magic Validation

From `src/sm2_model.c:63-81`:

```c
static int sm2_read_header(FILE* f, sm2_file_header* hdr) {
    if (fread(hdr, sizeof(sm2_file_header), 1, f) != 1) {
        return -1;
    }
    
    // Validate magic
    if (memcmp(hdr->magic, SM2_MAGIC, 8) != 0) {
        fprintf(stderr, "Invalid .sm2 file: bad magic\n");
        return -1;
    }
    
    if (hdr->version != SM2_VERSION) {
        fprintf(stderr, "Unsupported .sm2 version: %u (expected %d)\n", 
                hdr->version, SM2_VERSION);
        return -1;
    }
    
    return 0;
}
```

The magic string is 7 characters plus null terminator. The comparison uses 8 bytes to include the null.

## 2. File Structure Summary

```
.sm2 File Layout
├── Header (256 bytes, offset 0)
│   ├── Magic + version + metadata (0-31)
│   ├── Model dimensions (32-56)
│   ├── Hyperparameters (56-76)
│   ├── Token IDs (76-84)
│   ├── Offset/size fields (80-127)
│   └── Reserved (128-255)
├── Tokenizer Section (offset 256)
│   ├── Raw vocab JSON (~1.17 MB)
│   └── Size: 1,178,859 bytes (hardcoded in current impl)
└── Weights Section (offset varies by file)
    ├── tok_embeddings: [vocab_size, dim] header + F16 data
    ├── Layer weights (per layer):
    │   ├── input_layernorm: [1, dim] header + F16 data
    │   ├── q_proj: [dim, dim] header + F16 data
    │   ├── k_proj: [kv_dim, dim] header + F16 data
    │   ├── v_proj: [kv_dim, dim] header + F16 data
    │   ├── o_proj: [dim, dim] header + F16 data
    │   ├── post_attention_layernorm: [1, dim] header + F16 data
    │   ├── gate_proj: [hidden_dim, dim] header + F16 data
    │   ├── up_proj: [hidden_dim, dim] header + F16 data
    │   └── down_proj: [dim, hidden_dim] header + F16 data
    └── final_norm: [1, dim] header + F16 data
```

## 3. Header Layout (sm2_file_header)

### Struct Definition

```c
typedef struct {
    char magic[8];           // "SM2C001"
    uint32_t version;
    uint32_t variant_id;
    uint32_t quant_type;
    uint32_t flags;
    
    uint32_t vocab_size;
    uint32_t n_layers;
    uint32_t dim;
    uint32_t hidden_dim;
    uint32_t n_heads;
    uint32_t n_kv_heads;
    uint32_t head_dim;
    uint32_t max_seq_len;
    
    float rms_eps;
    float rope_theta;
    
    uint32_t bos_token_id;
    uint32_t eos_token_id;
    uint32_t pad_token_id;
    
    uint64_t tokenizer_offset;
    uint64_t tokenizer_size;
    uint64_t tensor_index_offset;
    uint64_t tensor_index_size;
    uint64_t weights_offset;
    uint64_t weights_size;
    uint64_t checksum;
} sm2_file_header;
```

### Byte Offset Table

| Field | Type | Size (bytes) | Byte Offset | Purpose |
|-------|------|--------------|-------------|---------|
| `magic` | char[8] | 8 | 0-7 | File magic: `"SM2C001"` |
| `version` | uint32_t | 4 | 8-11 | File format version (1) |
| `variant_id` | uint32_t | 4 | 12-15 | Model variant: 135, 360, or 1700 |
| `quant_type` | uint32_t | 4 | 16-19 | Quantization: 0=F16, 1=Q8_0, 2=Q4_0, 3=Q4_K |
| `flags` | uint32_t | 4 | 20-23 | Reserved flags |
| `vocab_size` | uint32_t | 4 | 24-27 | Vocabulary size (49152 for SmolLM2) |
| `n_layers` | uint32_t | 4 | 28-31 | Number of transformer layers |
| `dim` | uint32_t | 4 | 32-35 | Model dimension (embedding size) |
| `hidden_dim` | uint32_t | 4 | 36-39 | FFN hidden dimension |
| `n_heads` | uint32_t | 4 | 40-43 | Number of query heads |
| `n_kv_heads` | uint32_t | 4 | 44-47 | Number of key/value heads (GQA) |
| `head_dim` | uint32_t | 4 | 48-51 | Dimension per head (64) |
| `max_seq_len` | uint32_t | 4 | 52-55 | Maximum sequence length (8192) |
| `rms_eps` | float | 4 | 56-59 | RMSNorm epsilon (1e-5) |
| `rope_theta` | float | 4 | 60-63 | RoPE base frequency |
| `bos_token_id` | uint32_t | 4 | 64-67 | Beginning-of-sequence token ID |
| `eos_token_id` | uint32_t | 4 | 68-71 | End-of-sequence token ID |
| `pad_token_id` | uint32_t | 4 | 72-75 | Padding token ID |
| `tokenizer_offset` | uint64_t | 8 | 76-83 | Byte offset to tokenizer section |
| `tokenizer_size` | uint64_t | 8 | 84-91 | Size of tokenizer section |
| `tensor_index_offset` | uint64_t | 8 | 92-99 | Offset to tensor index (currently unused) |
| `tensor_index_size` | uint64_t | 8 | 100-107 | Size of tensor index |
| `weights_offset` | uint64_t | 8 | 108-115 | Byte offset to weights section |
| `weights_size` | uint64_t | 8 | 116-123 | Size of weights in bytes |
| `checksum` | uint64_t | 8 | 124-131 | File checksum |
| *reserved* | - | 124 | 132-255 | Padding to 256 bytes total |

**Total Header Size:** 256 bytes (enforced by `#define SM2_FILE_HEADER_SIZE 256`)

### Important: uint64_t Alignment Note

The header contains multiple `uint64_t` fields starting at offset 76. Due to C struct padding rules:
- The struct may have alignment requirements that affect field positions
- The header file shows uint64_t fields in the struct definition
- Current code uses hardcoded values (256, 1178859) as workarounds
- See Section 6 for details on tokenizer loading

## 7. Model Weights Structure

### From `include/smollm2.h:182-213`

```c
typedef struct {
    sm2_variant variant;
    sm2_quant_type quant_type;
    
    // Embedding + output (shared for tie_word_embeddings)
    sm2_tensor_f16* tok_embeddings;    // [vocab, dim]
    
    // Layer weights (allocated as contiguous arrays)
    // 1D weights: [n_layers * dim] of F16
    uint16_t* input_layernorm;          // [n_layers * dim]
    uint16_t* post_attention_layernorm; // [n_layers * dim]
    uint16_t* final_norm;               // [dim] (not per-layer)

    // 2D weights: [n_layers * rows * cols] of F16
    uint16_t* q_proj;                   // [n_layers * dim * dim]
    uint16_t* k_proj;                   // [n_layers * kv_dim * dim]
    uint16_t* v_proj;                   // [n_layers * kv_dim * dim]
    uint16_t* o_proj;                   // [n_layers * dim * dim]
    uint16_t* gate_proj;                // [n_layers * hidden_dim * dim]
    uint16_t* up_proj;                  // [n_layers * hidden_dim * dim]
    uint16_t* down_proj;                // [n_layers * dim * hidden_dim]

    sm2_tokenizer* tokenizer;           // loaded from .sm2 file
    
    int n_layers;
    int dim;
    int hidden_dim;
    int n_heads;
    int n_kv_heads;
    int head_dim;
    int vocab_size;
} sm2_model;
```

## 9. Weight Loading Sequence

### From `src/sm2_model.c:83-229`

```
1. Seek to weights_offset in file
2. Load tok_embeddings:
   - Read 4 bytes: rows
   - Read 4 bytes: cols
   - Read rows * cols * sizeof(uint16_t) bytes
3. For each layer (0 to n_layers-1):
   a. Read input_layernorm [1, dim]
   b. Read q_proj [dim, dim]
   c. Read k_proj [kv_dim, dim]
   d. Read v_proj [kv_dim, dim]
   e. Read o_proj [dim, dim]
   f. Read post_attention_layernorm [1, dim]
   g. Read gate_proj [hidden_dim, dim]
   h. Read up_proj [hidden_dim, dim]
   i. Read down_proj [dim, hidden_dim]
4. Load final_norm [1, dim]
```

### Key Dimension Relationships

- `kv_dim = n_kv_heads * head_dim`
- For 135M: kv_dim = 3 * 64 = 192
- For 360M: kv_dim = 5 * 64 = 320
- For 1.7B: kv_dim = 32 * 64 = 2048

## 13. Known Issues

### Issue 1: Hardcoded Tokenizer Location

The tokenizer loading uses hardcoded values (offset=256, size=1178859) instead of reading from header fields. This works but ignores header metadata.

### Issue 2: Header Field Alignment

Comment in code mentions potential alignment issues with uint64_t fields at offset 76-131. The hardcoded values work around this.

### Issue 3: uint16_t Weights Only

Current implementation loads all weights as uint16_t (F16). Quantized formats (Q4_K, Q8_0) are defined but not fully loaded in the current code.
