# SM2 File Format - Model Loading Architecture

**Spec Version:** 004
**Author:** Claude Code Analysis
**Date:** 2026-05-28
**Source:** `src/sm2_model.c` and `include/smollm2.h`

---

## Overview

This document provides complete technical documentation of the `.sm2` file format used by the SmolLM2 C implementation. It covers the binary layout, header structure, tokenizer format, and weight loading for SmolLM2-135M.

---

## 1. File Structure Summary

```
.sm2 File Layout
├── Header (256 bytes, offset 0)
│   ├── Magic + version + metadata (0-31)
│   ├── Model dimensions (32-56)
│   ├── Hyperparameters (56-76)
│   ├── Token IDs (76-84)
│   ├── Offset/size fields (80-127)
│   └── Reserved (128-255)
├── Tokenizer Section (offset 256)
│   ├── Raw vocab JSON (~1.17 MB)
│   └── Size: 1,178,859 bytes (hardcoded)
└── Weights Section (offset varies)
    ├── tok_embeddings + header
    ├── Layer 0 weights (9 tensors)
    ├── Layer 1 weights (9 tensors)
    └── ... (30 layers total)
    └── final_norm + header
```

## 2. Header Layout (sm2_file_header)

### Struct Definition (from `include/smollm2.h:89-119`)

```c
typedef struct {
    char magic[8];           // "SM2C001"
    uint32_t version;
    uint32_t variant_id;
    uint32_t quant_type;
    uint32_t flags;

    uint32_t vocab_size;
    uint32_t n_layers;
    uint32_t dim;
    uint32_t hidden_dim;
    uint32_t n_heads;
    uint32_t n_kv_heads;
    uint32_t head_dim;
    uint32_t max_seq_len;

    float rms_eps;
    float rope_theta;

    uint32_t bos_token_id;
    uint32_t eos_token_id;
    uint32_t pad_token_id;

    uint64_t tokenizer_offset;
    uint64_t tokenizer_size;
    uint64_t tensor_index_offset;
    uint64_t tensor_index_size;
    uint64_t weights_offset;
    uint64_t weights_size;
    uint64_t checksum;
} sm2_file_header;
```

**Total Header Size:** 256 bytes (enforced by `#define SM2_FILE_HEADER_SIZE 256`)

**Note:** The tokenizer is loaded using hardcoded values rather than header fields, making the header's `tokenizer_offset` and `tokenizer_size` effectively unused.

## 5. Weight Loading Order

### File Offset Calculation

Weights offset is determined in `src/sm2_model.c:99-102`:
```c
uint64_t weights_offset = hdr->weights_offset;
if (weights_offset == 0) {
    weights_offset = 256 + 1178859; // fallback for old files
}
```

**Weights Start Offset:**
```
256 (header) + 1,178,859 (tokenizer) = 1,179,115 bytes
```

### Per-Tensor Metadata Format

Each tensor is preceded by an 8-byte header:
- `uint32_t rows` - Number of rows
- `uint32_t cols` - Number of columns

Followed by `rows * cols * 2` bytes of F16 data.

### Weight Loading Sequence

```
1. tok_embeddings
2. Layer 0: input_layernorm
3. Layer 0: q_proj
4. Layer 0: k_proj
5. Layer 0: v_proj
6. Layer 0: o_proj
7. Layer 0: post_attention_layernorm
8. Layer 0: gate_proj
9. Layer 0: up_proj
10. Layer 0: down_proj
11. Layer 1: input_layernorm
... (repeat for all 30 layers)
32. Layer 29: down_proj
33. final_norm
```

## 8. Bugs and Anomalies

### 8.1 BUG: o_proj Shape Mismatch in Struct vs Code

**Location:** `include/smollm2.h:199` vs `src/sm2_model.c:185-189`

**Struct Declaration:**
```c
uint16_t* o_proj;  // [n_layers * dim * kv_dim]  <- INCORRECT COMMENT
```

**Code Comment:**
```c

```

**Actual Implementation:**
The code correctly uses `[dim, dim]` = [576, 576], but the struct comment incorrectly states `[n_layers * dim * kv_dim]`.

**Impact:** Low - The struct comment is misleading but code is correct.

### 8.2 BUG: Unused Header Offset Fields

**Location:** `src/sm2_model.c:271-277`

```c
// The header's tokenizer_offset and tokenizer_size fields are stored as uint32 at bytes 80-87
// (matching C struct layout). Old files may have garbage from uint64 misalignment.
```

The code ignores the header's `tokenizer_offset` and `tokenizer_size` fields entirely, using hardcoded values instead:
```c

```

**Impact:** Medium - If tokenizer size changes, file loading breaks.

### 8.3 BUG: weights_offset Fallback Logic

**Location:** `src/sm2_model.c:99-102`

```c
uint64_t weights_offset = hdr->weights_offset;
if (weights_offset == 0) {
    weights_offset = 256 + 1178859; // fallback for old files
}
```

**Issues:**
1. Assumes tokenizer size is exactly 1,178,859
2. If header has garbage (uninitialized), may use incorrect offset
3. No validation that weights_offset points to valid data

### 8.4 BUG: mmap Model Loading Incomplete

**Location:** `src/sm2_model.c:301-352`


**Issues:**
1. The mmap path only sets `tok_embeddings` pointer
2. Layer weights are never loaded in mmap path
3. Model is incomplete and will crash if used
4. No validation that file is large enough for claimed offsets

**Impact:** High - mmap model loading is broken.

### 8.5 WARNING: No Checksum Verification

**Location:** `src/sm2_model.c` (not present)

The header includes a `checksum` field at bytes 124-131, but no code reads or verifies it.

**Impact:** Low - No data integrity checking.

## 9. Memory Layout Analysis

### Row-Major vs Column-Major

All tensors use **row-major (C-style)** memory layout:
- 2D matrices stored as contiguous array with last dimension contiguous
- Index formula: `data[row * cols + col]`

### Contiguous Array Allocation

Layer weights are packed into single contiguous arrays:

```c
size_t input_ln_size  = (size_t)n_layers * dim * sizeof(uint16_t);
size_t q_size         = (size_t)n_layers * dim * dim * sizeof(uint16_t);
// ...
model->input_layernorm  = calloc(input_ln_size, 1);
model->q_proj          = calloc(q_size, 1);
```

Access pattern per layer `l`:
```c
uint16_t* layer_ln = model->input_layernorm + l * dim;  // [dim]
uint16_t* layer_q = model->q_proj + l * dim * dim;      // [dim, dim]
```

### Alignment Considerations

| Tensor | Alignment | Notes |
|--------|-----------|-------|
| F16 data | 2-byte | Natural alignment for uint16_t |
| Tensor headers | 4-byte | uint32_t rows/cols |
| All weights | Even | All F16 sizes are multiples of 2 |

**No alignment issues** - F16 values are 2 bytes, all offsets are even.

## 10. File Reading Patterns

### fread Usage

```c
// Read single value (count=1, size=N)
if (fread(&rows, 4, 1, f) != 1) { /* error */ }

// Read tensor data (count=1, size=total_bytes)
if (fread(data, total_bytes, 1, f) != 1) { /* error */ }
```

This pattern reads/writes in single large blocks rather than element-by-element, which is efficient for large tensors.

### Error Handling

All reads include error checking:
- Check return value of fread
- Print diagnostic message on failure
