# 008. RoPE Architecture Specification

## Overview

RoPE (Rotary Position Embedding) encodes absolute position information into query and key vectors through rotation. Unlike additive positional encodings (like sinusoidal in original Transformer), RoPE uses a rotation matrix that is multiplicative with the content.

## Mathematical Basis

### Core Concept

For a head dimension `d` (split into `d/2` pairs), each dimension pair `(i, i+half)` is rotated by an angle proportional to the position:

```
freq = theta^(-2i/d) * pos = pos / theta^(2i/d)
```

The rotation matrix applied to each pair:

```
[ cos(freq)  -sin(freq) ]   [ x[i]     ]
[ sin(freq)   cos(freq) ] * [ x[i+half] ]

x_out[i]     = x[i] * cos(freq) - x[i+half] * sin(freq)
x_out[i+half] = x[i] * sin(freq) + x[i+half] * cos(freq)
```

### Key Properties

1. **Relative position awareness**: The dot product of two rotated vectors depends only on their relative position
2. **Decay of interaction**: Higher dimensions (larger `i`) have faster oscillation (smaller wavelength)
3. **No extrapolation problem for short contexts**: Long contexts beyond training may degrade

### Wavelength Analysis

The wavelength (positions per full rotation) is `2 * pi * theta^(2i/d)`:

| i   | Wavelength (positions) |
|-----|------------------------|
| 0   | 2π ≈ 6.28              |
| 1   | 2π * 1.445 ≈ 9.08      |
| 15  | 2π * 31.62 ≈ 198.7     |
| 31  | 2π * 100000 ≈ 628319   |

Lower dimensions (small `i`) have short wavelengths; higher dimensions have very long wavelengths, meaning they change slowly with position.

## Implementation Summary

The RoPE implementation in smollm2.c uses **inline frequency computation** with no precomputation table. Each forward pass computes `powf(rope_theta, 2i/d)` for every head and dimension pair.

### Key Implementation Characteristics

| Aspect | Implementation |
|--------|----------------|
| Frequency computation | Inline (`powf` per pair per head) |
| Precomputation | Available but unused in current path |
| Theta values | 100000.0 (135M/360M), 130000.0 (1.7B) |
| Data precision | Single precision (`float`) |
| GQA support | Full support (separate RoPE for Q and KV heads) |

### Function: `sm2_rope()` (Primary Implementation)

**File**: `src/sm2_rope.c`, lines 44-80

```c
void sm2_rope(float* q, float* k, int head_dim, int pos,
              int n_heads, int n_kv_heads, float rope_theta) {
    int half = head_dim / 2;

    // For decode (pos=0), we need to apply RoPE for position 0
    // For generation, pos is kv_cache_len which increments each step
    int rope_pos = pos;

    // Apply to all Q heads
    for (int h = 0; h < n_heads; h++) {
        float* q_head = q + h * head_dim;
        for (int i = 0; i < half; i++) {
            float freq = (float)rope_pos / powf(rope_theta, (float)(2 * i) / (float)head_dim);
            float cos_theta = cosf(freq);
            float sin_theta = sinf(freq);

            float x0 = q_head[i];
            float x1 = q_head[i + half];

            q_head[i] = x0 * cos_theta - x1 * sin_theta;
            q_head[i + half] = x0 * sin_theta + x1 * cos_theta;
        }
    }

    // Apply to all K heads (GQA: may be fewer than Q heads)
    for (int h = 0; h < n_kv_heads; h++) {
        float* k_head = k + h * head_dim;
        for (int i = 0; i < half; i++) {
            float freq = (float)rope_pos / powf(rope_theta, (float)(2 * i) / (float)head_dim);
            float cos_theta = cosf(freq);
            float sin_theta = sinf(freq);

            float x0 = k_head[i];
            float x1 = k_head[i + half];

            k_head[i] = x0 * cos_theta - x1 * sin_theta;
            k_head[i + half] = x0 * sin_theta + x1 * cos_theta;
        }
    }
}
```

**Critical**: K is stored AFTER RoPE is applied. This is correct because:

## Verification: Formula Correctness

### Standard Llama RoPE Formula

The standard formula from the RoPE paper:

```
freq_i = theta^(-2i/d) * pos = pos / theta^(2i/d)
```

### Code Formula (Line 54)

```c
float freq = (float)rope_pos / powf(rope_theta, (float)(2 * i) / (float)head_dim);
```

### Verification

- `theta^(-2i/d)` = `1 / theta^(2i/d)`
- `pos * theta^(-2i/d)` = `pos / theta^(2i/d)`
- **Code matches standard formula** ✓

### Standard Rotation Direction

From the RoPE paper, the rotation applied to dimension pair `(x_m, x_n)` where `n = m + d/2`:

```
[x_m']   [cos(mθ)  -sin(mθ)] [x_m]
[x_n'] = [sin(mθ)   cos(mθ)] [x_n]
```

### Code Rotation (Lines 38-39)

```c
vec[i]     = x0 * cos_theta - x1 * sin_theta;  // x_out[m] = x_m*cos - x_n*sin
vec[i+half] = x0 * sin_theta + x1 * cos_theta; // x_out[n] = x_m*sin + x_n*cos
```

### Verification

- `x_out[i]` = `x[i] * cos - x[i+half] * sin` ✓
- `x_out[i+half]` = `x[i] * sin + x[i+half] * cos` ✓
- **Rotation direction matches standard** ✓

## Exact Computation Example

For SmolLM2-135M, position `pos = 5`, dimension pair `i = 0`:

```
freq = 5 / 100000^(0/64) = 5 / 1 = 5.0 radians

cos(5.0) ≈ 0.283662
sin(5.0) ≈ -0.958924

Given x[0] = 0.5, x[32] = 0.3:

x_out[0]  = 0.5 * 0.283662 - 0.3 * (-0.958924) = 0.141831 + 0.287677 = 0.429508
x_out[32] = 0.5 * (-0.958924) + 0.3 * 0.283662 = -0.479462 + 0.085099 = -0.394363
```

### Python Verification

```python
import numpy as np

theta = 100000.0
head_dim = 64
pos = 5
i = 0

# Frequency
freq = pos / (theta ** (2 * i / head_dim))
print(f"freq = {freq}")  # 5.0

# Rotation
x0, x1 = 0.5, 0.3
x_out_0 = x0 * np.cos(freq) - x1 * np.sin(freq)
x_out_1 = x0 * np.sin(freq) + x1 * np.cos(freq)
print(f"x_out[0] = {x_out_0:.6f}")  # 0.429508
print(f"x_out[1] = {x_out_1:.6f}")  # -0.394363
```

## Helper Functions

### `sm2_rope_build_freqs()`

Precomputes frequencies for all positions up to `max_seq`:

```c
void sm2_rope_build_freqs(float* freqs, int n_heads, int head_dim,
                          int max_seq, float theta) {
    for (int i = 0; i < head_dim / 2; i++) {
        float freq = 1.0f / powf(theta, (float)(2 * i) / (float)head_dim);
        for (int pos = 0; pos < max_seq; pos++) {
            freqs[pos * (head_dim / 2) + i] = freq * (float)pos;
        }
    }
}
```

Note: This computes `freqs[pos, i] = (pos / theta^(2i/d))` — same as inline formula.

### `sm2_rope_apply()`

Applies precomputed frequencies to a single vector:

```c
void sm2_rope_apply(float* vec, const float* freqs, int head_dim, int seq_pos) {
    int half = head_dim / 2;
    for (int i = 0; i < half; i++) {
        float freq = freqs[seq_pos * half + i];
        float cos_theta = cosf(freq);
        float sin_theta = sinf(freq);

        float x0 = vec[i];
        float x1 = vec[i + half];

        vec[i] = x0 * cos_theta - x1 * sin_theta;
        vec[i + half] = x0 * sin_theta + x1 * cos_theta;
    }
}
```

### `sm2_rope_full()`

Currently a wrapper that delegates to `sm2_rope`:

```c
void sm2_rope_full(float* q, float* k, int n_heads, int n_kv_heads,
                   int head_dim, int seq_len, float rope_theta,
                   float* output_q, float* output_k) {
    (void)seq_len;
    (void)output_q;
    (void)output_k;
    sm2_rope(q, k, head_dim, seq_len, n_heads, n_kv_heads, rope_theta);
}
```

**Note**: The unused parameters (`seq_len`, `output_q`, `output_k`) and function name suggest this may be intended for full-sequence RoPE during prefilling, but currently just delegates to the single-position `sm2_rope()`.

### Unused Precomputation Functions

The codebase includes `sm2_rope_build_freqs()` and `sm2_rope_apply()` for precomputed frequency tables, but these are **not currently used** in the inference path. The inline `sm2_rope()` recomputes frequencies on every call.

## RoPE Correctness Checklist

The following items MUST be correct for RoPE to produce meaningful results:

### 1. Frequency Formula
- [x] Formula is `freq = pos / theta^(2i/d)` (not `theta^(2i/d) * pos`)
- [x] Exponent is `2i/d` (not `i/d` or `4i/d`)
- [x] For i=0, freq equals position exactly

### 2. Rotation Matrix
- [x] Rotation matrix is `[cos, -sin; sin, cos]` (not transposed or negated)
- [x] First dimension gets `x*cos - y*sin`
- [x] Second dimension gets `x*sin + y*cos`

### 3. Dimension Pairing
- [x] Pair is `(i, i + head_dim/2)` for i in [0, head_dim/2)
- [x] For head_dim=64, pairs are: (0,32), (1,33), ..., (31,63)
- [x] No overlap or missed dimensions

### 4. Position Tracking
- [x] First token uses position 0
- [x] Each subsequent token increments position by 1
- [x] Prefill and decode use consistent position counting
- [x] seq_pos matches actual position in full sequence

### 5. Application Scope
- [x] RoPE applied to Q (query) vectors
- [x] RoPE applied to K (key) vectors
- [x] RoPE NOT applied to V (value) vectors
- [x] All Q heads receive RoPE
- [x] All K heads receive RoPE (including GQA/KV heads)

### 6. KV Cache
- [x] Keys stored AFTER RoPE application
- [x] Cache index correctly maps (head, position, dim)
- [x] Cache position matches seq_pos used for RoPE

### 7. Parameters
- [x] `rope_theta` matches model specification (100000.0 for SmolLM2-135M)
- [x] `head_dim` is correct (64 for all SmolLM2 variants)
- [x] Number of pairs is `head_dim / 2` = 32

### 8. Numerical Stability
- [x] Uses `cosf()`/`sinf()` for single precision
- [ ] For very large positions, consider modulo 2π for freq (not currently implemented)

## Potential Issues and Mitigations

### 1. Numerical Precision at Large Positions

For very long sequences (approaching max_seq_len=8192), frequencies become large:
- Position 8192 at i=0: freq = 8192 radians ≈ 1304 * 2π
- Floating point precision for `sin(8192)` may suffer

**Status**: Currently not mitigated; should be acceptable for max_seq=8192.

### 2. No Precomputation (Current Implementation)

The inline `sm2_rope()` computes `powf(rope_theta, 2i/d)` for every head and every pair on each forward pass.

**Performance Impact**: For SmolLM2-135M:
- Q heads: 9 heads * 32 pairs = 288 powf calls
- K heads: 3 heads * 32 pairs = 96 powf calls
- Total: 384 powf calls per layer per token

**Optimization Opportunity**: Precompute `theta_powers[i] = rope_theta^(2i/d)` once at startup, then multiply by position.

### 3. GQA (Grouped Query Attention) Correctness

SmolLM2-135M uses GQA with 9 Q heads and 3 KV heads. Each group of 3 Q heads shares 1 KV head.

**Current Implementation**: Correctly applies RoPE to all heads independently.

**Attention with Cache**: The `attention_with_cache()` function correctly maps Q heads to KV heads via `kv_head = qh / group_size`.
