# 011. Matmul and F16 Architecture

## Executive Summary

This document analyzes the matrix multiplication implementations and F16 conversion in the SmolLM2 C codebase. Key findings:

1. **DEAD CODE**: `sm2_matmul_ref.c` and `sm2_matmul_fast.c` are compiled but **never used** in the actual inference path
2. **All matmul operations use inline hand-written loops with Kahan summation** in `sm2_context.c`
3. **F16 conversion has a denormalized number bug** in the unused matmul files

---

## 2. Actual Matmul Implementation

All matmul operations are implemented inline in `sm2_context.c:layer_forward()` using hand-written loops with **Kahan summation** for numerical stability.

### 2.1 Kahan Summation Pattern

```c
float sum = 0.0f;
float c = 0.0f;  // Compensation for lost low-order bits
for (int j = 0; j < k; j++) {
    float w = sm2_f16_to_float(weight[offset + i * k + j]);
    float y = xb_out[j] * w - c;  // Compensated multiplication
    float t = sum + y;
    c = (t - sum) - y;             // Track error
    sum = t;
}
```

### 2.2 Projection Matrices and Directions

All projection weights follow the convention: `[rows, cols]` stored row-major.

| Projection | Weight Shape | Output Shape | Computation |
|------------|-------------|--------------|-------------|
| **Q** | `[dim, dim]` = 576x576 | `[dim]` = 576 | `q[i] = sum_j xb_out[j] * q_proj[i*dim + j]` |
| **K** | `[kv_dim, dim]` = 144x576 | `[kv_dim]` = 144 | `k[i] = sum_j xb_out[j] * k_proj[i*dim + j]` |
| **V** | `[kv_dim, dim]` = 144x576 | `[kv_dim]` = 144 | `v[i] = sum_j xb_out[j] * v_proj[i*dim + j]` |
| **O** | `[dim, dim]` = 576x576 | `[dim]` = 576 | `xb_out[i] = sum_j attn_out[j] * o_proj[i*dim + j]` |
| **Gate** | `[hidden_dim, dim]` = 1536x576 | `[hidden_dim]` = 1536 | `gate[i] = sum_j xb_out[j] * gate_proj[i*dim + j]` |
| **Up** | `[hidden_dim, dim]` = 1536x576 | `[hidden_dim]` = 1536 | `up[i] = sum_j xb_out[j] * up_proj[i*dim + j]` |
| **Down** | `[dim, hidden_dim]` = 576x1536 | `[dim]` = 576 | `sum_j gate_out[j] * down_proj[i*hidden_dim + j]` |

### 2.3 Matmul Direction Verification

All projections compute: `output = input @ W^T` (transposed weight)

**Q Projection (lines 225-236):**
```c
// q_proj is [dim, dim] stored row-major
// q[i*dim + j] = weight at row i, col j
for (int i = 0; i < dim; i++) {
    float sum = 0.0f;
    for (int j = 0; j < dim; j++) {
        float w = sm2_f16_to_float(model->q_proj[q_off + i * dim + j]);
        sum += xb_out[j] * w;
    }
    q[i] = sum;
}
```
- `xb_out` is `[1 x dim]`
- `q_proj` is `[dim x dim]`
- `q` is `[1 x dim]`
- **VERDICT: CORRECT** - Standard `x @ W^T` where W is row-major

**Logits Computation (lines 433-446):**
```c

// logits[vocab_id] = dot_product(hidden, embed[vocab_id])
```

## 3. F16 Conversion Analysis

### 3.1 sm2_f16_to_float (sm2_utils.h - ACTIVE)

This is the **active** F16 conversion used throughout inference:

```c
static inline float sm2_f16_to_float(uint16_t h) {
    unsigned int bits = h;
    int sign = (bits >> 15) & 1;
    int exp = (bits >> 10) & 0x1F;
    int frac = bits & 0x3FF;
    float result;

    if (exp == 0) {
        // Denormalized: (frac / 1024) * 2^(-14)
        result = (float)frac / 65536.0f;  // 1024 * 2^(-14) = 65536
    } else if (exp == 31) {
        result = (frac == 0) ? 1.0f / 0.0f : 0.0f / 0.0f;  // inf or nan
    } else {
        // Normalized: (1 + frac/1024) * 2^(exp-15)
        result = (1.0f + (float)frac / 1024.0f) * powf(2.0f, (float)(exp - 15));
    }

    return sign ? -result : result;
}
```

**Formula Summary:**
| Case | Condition | Formula |
|------|-----------|---------|
| Zero/Denormal | exp == 0 | `frac / 65536.0f` |
| Inf/NaN | exp == 31 | `1.0/0.0` or `0.0/0.0` |
| Normal | 1 <= exp <= 30 | `(1 + frac/1024) * 2^(exp-15)` |

### 3.2 Dead Code F16 Converters

**sm2_matmul_ref.c (line 16-32):**

```c
    // ...
    if (exp == 0) {

    }

```

```c
    // Same bug as sm2_matmul_ref.c
    if (exp == 0) {
        result = (float)frac / 1024.0f;  // BUG: Should be 65536!
    }
}
```

### 3.3 F16 Precision Analysis

**Denormalized Number Bug (UNUSED CODE):**

The denormalized case in `sm2_matmul_ref.c` and `sm2_matmul_fast.c` is **incorrect**:
- **Wrong**: `frac / 1024.0f`
- **Correct**: `frac / 65536.0f` = `frac / 1024.0f * 2^(-14)`

The IEEE-754 float16 denormalized format:
- Stored bits: `[sign=1][exp=0][frac=10bits]`
- Value = `(-1)^sign * (frac / 1024) * 2^(-14)`
- Which equals `frac / (1024 * 2^14)` = `frac / 65536`

**However**: Since these functions are never called, this bug has **no effect** on inference.

### 3.4 sm2_utils.h Formula is Correct

The active `sm2_f16_to_float` in `sm2_utils.h` correctly implements:
```c
result = (float)frac / 65536.0f;  // Correct for denormalized F16
```

**No precision loss bugs** in the active code path.

## 4. Performance Characteristics

### 4.1 Current Implementation

The inline matmul loops in `sm2_context.c`:
- Use **Kahan summation** for numerical stability
- Convert F16 to float **inline** per weight access
- No SIMD or architecture-specific optimizations
- Complexity: O(n_layers * n_tokens * dim^2) for prefill

### 4.2 Optimization Opportunities

Since `sm2_matmul_fast.c` is dead code, consider either:
1. **Removing** dead code to reduce binary size
2. **Integrating** optimized matmul into hot path
