# KV Cache Architecture

## Overview

The KV cache stores cached Key and Value tensors from all attention layers, enabling efficient autoregressive decoding by reusing computation from previously processed tokens. This is critical for Grouped Query Attention (GQA) efficiency in SmolLM2 variants.

### KV Cache Implementation Files

| File | Purpose |
|------|---------|
| `src/kv/sm2_kv_pool.c` | KV pool management - page allocation/free |
| `src/kv/sm2_kv_page.c` | Page-based K/V read/write operations |
| `src/kv/sm2_kv_quant_q8.c` | Q8 (8-bit) quantization for KV cache |
| `src/kv/sm2_kv_quant_q4.c` | Q4 (4-bit) quantization for KV cache |

### Attention Types Summary

| Type | File | Purpose | Status |
|------|------|---------|--------|
| **Standard** | `src/sm2_context.c:attention_with_cache()` | Default decode attention with flat cache | **ACTIVE** |
| **Prefill** | `src/attention/sm2_attn_prefill.c` | Full attention for prompt processing | Available |
| **Flash Prefill** | `src/attention/sm2_attn_flash_prefill.c` | Online softmax with tile-based processing | Available |
| **Paged** | `src/attention/sm2_attn_paged.c` | Page-based KV storage with online softmax | Available |

The main implementation uses `attention_with_cache()` in `sm2_context.c`, which is called from `layer_forward()` for both prefill and decode phases. Alternative implementations exist in the attention/ directory for future optimization.

## KV Cache Memory Layout

### Allocation (`sm2_create_context`)

```
sm2_scratch.k_cache: float**[n_layers]
sm2_scratch.v_cache: float**[n_layers]

Each layer l has: float[(n_kv_heads * max_seq * head_dim)]
```

**SmolLM2-135M dimensions:**

| Parameter | Value |
|-----------|-------|
| `n_layers` | 30 |
| `n_kv_heads` | 3 |
| `max_seq_len` | 8192 |
| `head_dim` | 64 |
| kv_dim (`n_kv_heads * head_dim`) | 192 |

**Per-layer allocation size:**
```
kv_per_layer = n_kv_heads * max_seq * head_dim
             = 3 * 8192 * 64
             = 1,572,864 floats
             = ~6.0 MB (float32)
```

**Total KV cache memory (both K and V):**
```
Total K = 30 * 1,572,864 * 4 bytes = ~180 MB
Total V = 30 * 1,572,864 * 4 bytes = ~180 MB
Total   = ~360 MB
```

## Indexing Formula

### Cache Index Computation

The flat memory index for accessing a specific `(head, position, dimension)` element:

```c
// From layer_forward (lines 273-278):
int cache_idx = head * ctx->params.max_context * kv_head_dim
              + seq_pos * kv_head_dim
              + d;
```

**Formula breakdown:**
```
cache_idx = (head * max_seq + seq_pos) * head_dim + d

Where:
  head      = [0, n_kv_heads)    - which KV head
  seq_pos   = [0, max_seq)       - position in sequence
  d         = [0, head_dim)      - dimension within head
```

**Indexing diagram:**

```
Layout for one layer (n_kv_heads=3, max_seq=8192, head_dim=64):

Address range          Contents
────────────────────────────────────────────────────────────────
[0      .. 524287]     KV head 0: positions 0..8191, dims 0..63
[524288 .. 1048575]    KV head 1: positions 0..8191, dims 0..63
[1048576 .. 1572863]   KV head 2: positions 0..8191, dims 0..63

Within KV head 0:
  [0     .. 63]        position 0: dims 0..63
  [64    .. 127]       position 1: dims 0..63
  ...
  [524224 .. 524287]   position 8191: dims 0..63
```

**Example calculation for SmolLM2-135M:**
```
Accessing: head=2, position=5000, dim=32

cache_idx = 2 * 8192 * 64 + 5000 * 64 + 32
          = 1048576 + 320000 + 32
          = 1368608
```

## KV Pool Management

### Data Structures

```c
// KV page - stores 16 tokens of K and V for one layer/head
typedef struct {
    uint32_t id;
    uint16_t used;           // tokens in use (0-16)
    uint16_t refcount;       // reference count
    uint32_t next_free;      // free list link
    
    // Data pointers (can be F16, Q8, Q4, or TURBO2)
    uint8_t* k_data;
    uint8_t* v_data;
    uint8_t* k_scale;
    uint8_t* v_scale;
} sm2_kv_page;

// KV pool - global pool of pages
typedef struct {
    int n_layers;
    int n_kv_heads;
    int head_dim;
    int page_tokens;         // 16
    sm2_kv_dtype dtype;
    
    int max_pages;
    sm2_kv_page* pages;
    uint32_t* free_stack;
    int free_top;
} sm2_kv_pool;
```

### Supported Data Types

```c
typedef enum {
    SM2_KV_F16,      // 2 bytes per element (float16)
    SM2_KV_Q8,       // 1 byte per element (quantized 8-bit)
    SM2_KV_Q4,       // 0.5 bytes per element (quantized 4-bit)
    SM2_KV_TURBO2,   // 0.25 bytes per element (turbo mode)
    SM2_KV_MIXED     // mixed precision
} sm2_kv_dtype;
```

### Pool Initialization (`sm2_kv_pool_init`)

```c
int sm2_kv_pool_init(sm2_kv_pool* pool, int n_layers, int n_kv_heads, 
                     int max_pages, sm2_kv_dtype dtype);
```

**Initialization steps:**
1. Initialize pool metadata (n_layers, n_kv_heads, head_dim=64, page_tokens=16)
2. Allocate array of `sm2_kv_page` structures
3. Allocate free stack for page tracking
4. Initialize free stack with all page IDs (stack grows from top)
5. Calculate bytes per element based on dtype:
   - F16: 2 bytes
   - Q8: 1 byte
   - Q4: 0.5 bytes
   - TURBO2: 0.25 bytes
6. Allocate K/V data buffers for each page (K and V separately)

**Memory per page calculation:**
```c
size_t kv_bytes_per_head = n_kv_heads * SM2_KV_PAGE_TOKENS * 64 * bytes_per_element;
size_t page_bytes = n_layers * kv_bytes_per_head * 2; // K + V
```

### Pool Deallocation (`sm2_kv_pool_free`)

```c
void sm2_kv_pool_free(sm2_kv_pool* pool);
```

Frees all allocated memory:
- Each page's k_data, v_data, k_scale, v_scale buffers
- Page array
- Free stack

### Page Allocation (`sm2_kv_alloc_page`)

```c
uint32_t sm2_kv_alloc_page(sm2_kv_pool* pool);
```

**Algorithm:** LIFO free stack pop
- Decrements `free_top` and returns `free_stack[free_top]`
- Returns 0 if no free pages available
- O(1) allocation time

### Page Deallocation (`sm2_kv_free_page`)

```c
void sm2_kv_free_page(sm2_kv_pool* pool, uint32_t page_id);
```

**Algorithm:** LIFO free stack push
- Resets page's `used` to 0
- Pushes page_id onto free stack
- O(1) deallocation time

### Pool Statistics (`sm2_kv_pool_stats`)

```c
int sm2_kv_pool_stats(sm2_kv_pool* pool, int* out_free, int* out_used);
```

Returns:
- `out_free`: `free_top` (available pages)
- `out_used`: `max_pages - free_top` (allocated pages)

## Page-Based Caching

### Page Configuration

```c
#define SM2_KV_PAGE_TOKENS 16
```

Each KV page stores exactly 16 tokens per layer/head combination.

### Memory Layout per Page

```
Page layout: [n_layers][n_kv_heads][16 tokens][64 dims]

For 135M (30 layers, 3 KV heads):
- K data: 30 * 3 * 16 * 64 * bytes_per_element
- V data: 30 * 3 * 16 * 64 * bytes_per_element
- Scales: 30 * 3 * sizeof(float) * 2 (K and V)
```

### Token Write (`sm2_kv_write_token`)

```c
int sm2_kv_write_token(sm2_kv_page* page, int offset, int kv_head,
                       const float* k, const float* v);
```

**Parameters:**
- `page`: Target page
- `offset`: Token position within page (0-15)
- `kv_head`: Which KV head (0-2 for 135M)
- `k`, `v`: 64-dimensional K/V vectors

**Memory layout:**
```c
size_t head_offset = kv_head * SM2_KV_PAGE_TOKENS * 64;
size_t token_offset = head_offset + offset * 64;
```

**Status:** Returns -1 if offset >= 16 (out of bounds)

### Token Read (`sm2_kv_read_token`)

```c
int sm2_kv_read_token(sm2_kv_page* page, int offset, int kv_head,
                      float* k_out, float* v_out);
```

Reads K/V from page into output buffers. Returns -1 if `offset >= page->used`.

### Quantized Token Write (`sm2_kv_write_token_q8`)

```c
int sm2_kv_write_token_q8(sm2_kv_page* page, int offset, int kv_head,
                          const float* k, const float* v,
                          float k_scale, float v_scale);
```

Writes quantized K/V using provided scales:
```c
k_base[token_offset * 64 + d] = (int8_t)(k[d] / k_scale);
v_base[token_offset * 64 + d] = (int8_t)(v[d] / v_scale);
```

Scales are stored per-head in `page->k_scale[kv_head]` and `page->v_scale[kv_head]`.

### Page Clear (`sm2_kv_page_clear`)

```c
void sm2_kv_page_clear(sm2_kv_page* page);
```

Resets page state:
- `used = 0`
- `refcount = 0`

## Q8 Quantization (`src/kv/sm2_kv_quant_q8.c`)

### Quantization Scheme

Q8 uses 8-bit signed integers with per-block scaling:
- Range: [-127, 127] (symmetric around 0)
- Scale: `max_abs_value / 127.0f`
- Minimum scale: 1e-7f (prevent division by zero)

### Quantize Single Block (`sm2_kv_quantize_q8`)

```c
void sm2_kv_quantize_q8(float* out, const float* in, int n, float* scale);
```

1. Find maximum absolute value across n elements
2. Compute scale: `scale = max_val / 127.0f`
3. Quantize each value: `q = round(in[i] / scale)`
4. Clamp to [-127, 127]
5. Store quantized as float (will be cast to int8_t)

**Example:**
```
Input: [1.5, -0.5, 2.0, 0.0]
max_val = 2.0
scale = 2.0 / 127 = 0.0157
Output: [95, -32, 127, 0] (as floats)
```

### Dequantize (`sm2_kv_dequant_q8`)

```c
void sm2_kv_dequant_q8(float* out, const float* in, int n, float scale);
```

Simple multiplication: `out[i] = in[i] * scale`

### Quantize Block (`sm2_kv_quantize_block_q8`)

```c
int sm2_kv_quantize_block_q8(
    float* k_out, float* k_scale_out,
    float* v_out, float* v_scale_out,
    const float* k_in, const float* v_in,
    int n_kv_heads, int n_tokens
);
```

Quantizes entire KV block:
- Iterates over all KV heads
- Quantizes K and V separately per head
- Stores per-head scales

## Q4 Quantization (`src/kv/sm2_kv_quant_q4.c`)

### Quantization Scheme

Q4 uses 4-bit signed integers packed 2 per byte:
- Range: [-7, 7] (16 discrete values, symmetric around 0)
- Scale: `max_abs_value / 7.0f`
- Minimum scale: 1e-7f (prevent division by zero)
- Rounding: Round-away-from-zero (positive values round up, negative round down)

**Note:** This implementation uses **per-tensor scaling** (one scale per entire KV head), not per-block scaling. This simplifies the format at the cost of precision for non-uniform distributions. Contrast with TURBO2's per-channel (K) and per-token (V) granularity.

### Quantize Single Block (`sm2_kv_quantize_q4`)

```c
void sm2_kv_quantize_q4(float* out, const float* in, int n, float* scale);
```

1. Find maximum absolute value across n elements
2. Compute scale: `scale = max_val / 7.0f` (minimum 1e-7f)
3. Quantize each value: `q = round(in[i] / scale)`
4. Round away from zero: `q = v >= 0 ? v + 0.5f : v - 0.5f`
5. Clamp to [-7, 7]
6. Store quantized as float (will be packed to nibbles)

**Example:**
```
Input: [1.5, -0.5, 2.0, 0.0]
max_val = 2.0
scale = 2.0 / 7 = 0.2857
Output: [5, -2, 7, 0] (as floats, to be packed)
```

### Dequantize Q4 (`sm2_kv_dequant_q4`)

```c
void sm2_kv_dequant_q4(float* out, const float* in, int n, float scale);
```

Simple multiplication: `out[i] = in[i] * scale`

### Pack Q4 Nibbles (`sm2_kv_pack_q4`)

```c
void sm2_kv_pack_q4(uint8_t* out, const float* in, int n);
```

Packs quantized Q4 values (stored as floats in range [-7, 7]) into bytes:
- Even indices (0, 2, 4...) go to low nibble (bits 0-3)
- Odd indices (1, 3, 5...) go to high nibble (bits 4-7)

```c
// Each byte contains 2 nibbles (4 bits each)
out[i] = (in[2*i] & 0x0F) | ((in[2*i + 1] & 0x0F) << 4);
```

**Example:**
```
Input: [5, -2, 7, 0, 3, 1, -5, 6]
Input (masked): [5, 2, 7, 0, 3, 1, 5, 6]
Packed bytes: [0x25, 0x07, 0x13, 0x65]
  Byte 0: low=5, high=2 -> 0x25
  Byte 1: low=7, high=0 -> 0x07
  Byte 2: low=3, high=1 -> 0x13
  Byte 3: low=5, high=6 -> 0x65
```

### Unpack Q4 Nibbles (`sm2_kv_unpack_q4`)

```c
void sm2_kv_unpack_q4(float* out, const uint8_t* in, int n);
```

Extracts individual Q4 values from packed bytes:
```c
int byte_idx = i / 2;
int shift = (i % 2) * 4;  // 0 for even, 4 for odd
out[i] = (float)((in[byte_idx] >> shift) & 0x0F);
```

### Memory Layout

For a single KV head with n_tokens:

| Component | Size | Notes |
|-----------|------|-------|
| Quantized data | n_tokens * 64 / 2 bytes | Packed 2 nibbles per byte |
| Scale | 4 bytes | Single float32 per head |
| **Total** | **4 + (n_tokens * 32) bytes** | |

### Per-Layer Memory (135M, max_seq=8192, 3 KV heads)

```
K cache:
  Quantized: 3 * 8192 * 64 / 2 = 786,432 bytes
  Scales: 3 * 4 = 12 bytes
  Total K: ~787 KB

V cache:
  Quantized: 3 * 8192 * 64 / 2 = 786,432 bytes
  Scales: 3 * 4 = 12 bytes
  Total V: ~787 KB

Per-layer total: ~1.57 MB
All 30 layers: ~47 MB (K + V combined)
```

### Comparison with Other Quantization Modes

| Mode | Per-Layer K | Per-Layer V | Per-Layer Total | All Layers | Compression |
|------|-------------|-------------|-----------------|------------|-------------|
| F16 | 6.0 MB | 6.0 MB | 12.0 MB | 360 MB | 1.0x |
| Q8 | 1.57 MB | 1.57 MB | 3.14 MB | 94 MB | 3.8x |
| **Q4** | 0.79 MB | 0.79 MB | 1.57 MB | **47 MB** | **7.7x** |
| TURBO2 | 0.19 MB | 0.20 MB | 0.39 MB | 12 MB | 30x |

**Note:** TURBO2 achieves better compression by using different scale granularities per K and V (per-channel K, per-token V), allowing more aggressive packing.

## Attention with Cache (`attention_with_cache`)

### Function Signature
```c
static void attention_with_cache(float* out, const float* q, int layer,
                                  sm2_context* ctx, sm2_model* model)
```

### Key Variables

```c
int n_heads = model->n_heads;           // 9 (135M)
int n_kv_heads = model->n_kv_heads;    // 3 (135M)
int head_dim = model->head_dim;         // 64
int group_size = n_heads / n_kv_heads; // 3

// Current sequence length in cache (+1 for current token being processed)
int kv_seq = ctx->scratch.kv_cache_len + 1;
```

### Attention Computation Steps

**Step 1: Query loading**
```c
// For each query head qh:
// q is [n_heads * head_dim], so q[qh * head_dim + d] gets dimension d of head qh
float qv = q[qh * head_dim + d];
```

**Step 2: Key access and score computation**
```c
// Iterate over all cached positions
for (int pos = 0; pos < kv_seq; pos++) {
    float dot = 0.0f;
    for (int d = 0; d < head_dim; d++) {
        float qv = q[qh * head_dim + d];
        int cache_idx = kv_head * ctx->params.max_context * head_dim
                       + pos * head_dim + d;
        float kv = ctx->scratch.k_cache[layer][cache_idx];
        dot += qv * kv;
    }
    dot *= 1.0f / sqrtf((float)head_dim);  // Scale by 1/sqrt(64) = 0.125
    scores[pos] = dot;
}
```

**Step 3: Softmax (numerically stable)**
```c
// Find max for numerical stability
float max_score = -1e9f;
for (int pos = 0; pos < kv_seq; pos++) {
    if (scores[pos] > max_score) max_score = scores[pos];
}

// Compute exp and sum
float sum_exp = 0.0f;
for (int pos = 0; pos < kv_seq; pos++) {
    scores[pos] = expf(scores[pos] - max_score);
    sum_exp += scores[pos];
}
```

**Step 4: Weighted value sum**
```c
for (int d = 0; d < head_dim; d++) {
    float sum = 0.0f;
    for (int pos = 0; pos < kv_seq; pos++) {
        int cache_idx = kv_head * ctx->params.max_context * head_dim
                       + pos * head_dim + d;
        float vv = ctx->scratch.v_cache[layer][cache_idx];
        sum += scores[pos] * vv;
    }
    out[qh * head_dim + d] = sum / sum_exp;
}
```

## Cache Storage (`layer_forward`)

### K/V Projection Output

After Q/K/V projections and RoPE, the vectors are:

```c
// k: [n_kv_heads * head_dim] = [3 * 64]
// v: [n_kv_heads * head_dim] = [3 * 64]

// k[head * head_dim + d] = key for dimension d of head
// v[head * head_dim + d] = value for dimension d of head
```

### Storage to Cache
```c
// From layer_forward lines 271-279:
int kv_head_dim = model->head_dim;
for (int head = 0; head < model->n_kv_heads; head++) {
    for (int d = 0; d < kv_head_dim; d++) {
        int cache_idx = head * ctx->params.max_context * kv_head_dim
                       + seq_pos * kv_head_dim + d;
        ctx->scratch.k_cache[layer][cache_idx] = k[head * kv_head_dim + d];
        ctx->scratch.v_cache[layer][cache_idx] = v[head * kv_head_dim + d];
    }
}
```

## Prefill Phase (`sm2_prefill`)

### Sequential Token Processing

```c
int sm2_prefill(sm2_context* ctx, const int* tokens, int n_tokens) {
    for (int t = 0; t < n_tokens; t++) {
        int seq_pos = t;  // Absolute position in full sequence

        // Embed token t
        embedding_lookup(ctx->scratch.x, tokens[t], model->tok_embeddings);

        // Forward through all layers
        for (int layer = 0; layer < model->n_layers; layer++) {
            layer_forward(ctx->scratch.xb, ctx->scratch.x, layer, model, ctx, seq_pos);
            // Swap buffers...
        }

        // Update cache length after each token
        ctx->scratch.kv_cache_len = t + 1;
        ctx->last_token = tokens[t];
    }
    // ...
}
```

```
After token 3: kv_cache_len = 4, positions [0, 1, 2, 3] filled
```

## Decode Phase (`sm2_decode_next`)

### Single Token Generation

```c
int sm2_decode_next(sm2_context* ctx, int* out_token) {
    // seq_pos is position for the new token to be cached
    int seq_pos = ctx->scratch.kv_cache_len;

    // Embed last_token (autoregressive: output becomes next input)
    embedding_lookup(ctx->scratch.x, ctx->last_token, ctx->model->tok_embeddings);

    // Forward through all layers
    for (int layer = 0; layer < ctx->model->n_layers; layer++) {
        layer_forward(ctx->scratch.xb, ctx->scratch.x, layer, ctx->model, ctx, seq_pos);
        // K/V for this position stored in layer_forward
    }

    // Sample from logits
    int token = sm2_sample_token(ctx->scratch.logits, ...);

    // Update cache length
    ctx->scratch.kv_cache_len = seq_pos + 1;
    ctx->pos++;
    ctx->last_token = token;

    return token;
}
```

**Cache state during decode (after prefill with 5 tokens):**
```
Before decode 1: kv_cache_len = 5, seq_pos = 5
  -> attention_with_cache uses kv_seq = 5 + 1 = 6 positions [0..5]
  -> K/V stored at position 5
  -> kv_cache_len becomes 6

Before decode 2: kv_cache_len = 6, seq_pos = 6
  -> attention_with_cache uses kv_seq = 6 + 1 = 7 positions [0..6]
  -> K/V stored at position 6
  -> kv_cache_len becomes 7
```

## Indexing Verification Checklist

### 1. Position Increment Correctness

| Phase | Position Source | Update Mechanism |
|-------|-----------------|------------------|
| Prefill | `t` (loop index) | `kv_cache_len = t + 1` after each token |
| Decode | `kv_cache_len` | `kv_cache_len = seq_pos + 1` after forward |

**Status: CORRECT**

### 2. Cache Index Formula Consistency

Used in two places with identical formula:

1. **Storage** (`layer_forward` lines 275-277):
```c

              + seq_pos * kv_head_dim + d;
```

2. **Access** (`attention_with_cache` lines 150, 170):
```c
int cache_idx = kv_head * ctx->params.max_context * head_dim
              + pos * head_dim + d;
```

**Status: CORRECT** - Both use the same formula structure.

### 3. kv_seq Calculation

```c
// attention_with_cache line 136:
// K/V for current position already stored by layer_forward
// So we must attend over kv_cache_len + 1 positions
int kv_seq = ctx->scratch.kv_cache_len + 1;
```

**Logic:** When `attention_with_cache` is called, `layer_forward` has already stored the current token's K/V at position `seq_pos`. The cache contains `kv_cache_len` positions (0 to kv_cache_len-1), and the current position is `seq_pos = kv_cache_len`. So we need to attend over `kv_cache_len + 1` positions.

**Status: CORRECT**

### 4. GQA Head Mapping


**Verification for 135M:**

## Potential Issues and Observations

### 1. No Bounds Checking

The code does not verify `seq_pos < max_context` before accessing cache. If `kv_cache_len` reaches `max_context` (8192), the next decode will write beyond allocated memory.

**Mitigation:** Caller should enforce max_output limits.

### 2. Sequential Attention O(max_seq)

The current `attention_with_cache` iterates over all cached positions sequentially. For long contexts, this becomes a bottleneck. Optimizations could include:
- Flash attention (softmax tiling)
- KV cache quantization
- Page-based cache management (partially defined in header, not implemented)

### 3. Scratch Buffer Ping-Pong

```c
// sm2_prefill and sm2_decode_next both do:
float* tmp = ctx->scratch.x;
ctx->scratch.x = ctx->scratch.xb;
ctx->scratch.xb = tmp;
```

After the layer loop, `scratch.x` holds the final output. This pattern is correct.

### 4. Repetition Penalty Tracking

The `recent_tokens` ring buffer is separate from the KV cache:
```c
// sm2_prefill: tracks prompt tokens
ctx->scratch.recent_tokens[t] = tokens[t];

// sm2_decode_next: tracks generated tokens
ctx->scratch.recent_tokens[ctx->scratch.kv_cache_len] = token;
```

This tracks token IDs for repetition penalty, not K/V vectors.

## KV Cache Quantization Modes

### Supported Modes

| Mode | Bits/Value | Memory (135M, ctx=1024) | Implementation |
|------|------------|--------------------------|----------------|
| F16  | 16-bit float | ~23 MB                   | Default (no quantization) |
| Q8   | 8-bit per-token | ~12 MB              | `src/kv/sm2_kv_quant_q8.c` |
| Q4   | 4-bit per-token | ~6 MB               | `src/kv/sm2_kv_quant_q4.c` |
| TURBO2 | ~2-4 bits effective | ~3 MB          | `src/kv/sm2_kv_turbo2.c` |

### TURBO2 Quantization Scheme

TURBO2 is a KIVI-like quantization scheme optimized for KV cache memory reduction. It uses asymmetric precision for K and V matrices to achieve ~3.9x compression with minimal accuracy impact.

#### Quantization Strategy

| Component | Quantization | Scale Granularity | Values |
|-----------|--------------|-------------------|--------|
| K (Key) | Per-channel | `n_kv_heads * head_dim` scales | -7 to +7 |
| V (Value) | Per-token | `n_tokens` scales | -7 to +7 |

#### K (Key) - Per-Channel Quantization

For each (head, dimension) channel, computes scale from max absolute value across all tokens:

```c
// For each head h, dimension d:
max_val = max(|k[h,t,d]|) over all tokens t
scale = max_val / 7.0f

// Quantize and clamp:
q = (int)(v / scale + 0.5f)
q = clamp(q, -7, 7)
```

**Rationale:** Attention scores depend on angular relationships across dimensions. Per-channel scaling preserves relative magnitude relationships critical for accurate attention weighting.

#### V (Value) - Per-Token Quantization

For each token position, computes scale from max absolute value across all dimensions:

```c
// For each token t:
max_val = max(|v[t,d]|) over all dimensions d
scale = max_val / 7.0f

// Quantize and clamp:
q = (int)(v / scale + 0.5f)
q = clamp(q, -7, 7)
```

**Rationale:** Values accumulate via weighted sum in attention. Per-token scaling maintains relative magnitudes within each position.

### Compression Ratio Analysis

For SmolLM2-135M (3 KV heads, head_dim=64, context=1024):

```
Float32 baseline (per-layer):
  K: 3 * 1024 * 64 * 4 bytes = 768 KB
  V: 3 * 1024 * 64 * 4 bytes = 768 KB
  Total: 1.5 MB per layer

TURBO2 (per-layer):
  K quantized data: 3 * 1024 * 64 values * 1 byte = 192 KB
  K scales: 3 * 64 * 4 bytes = 768 bytes
  V quantized data: 3 * 1024 * 64 values * 1 byte = 192 KB
  V scales: 1024 * 4 bytes = 4 KB
  Total: ~389 KB per layer

Compression: 1.5 MB -> 389 KB = ~3.9x reduction
```

### Accuracy Impact

**Expected:** Minimal quality degradation for most tasks.

| Factor | Impact |
|--------|--------|
| Per-channel K scaling | Critical - preserves attention score accuracy |
| Per-token V scaling | Lower impact - values aggregate via weighted sum |
| 8-level quantization | Sufficient resolution for relative comparisons |
| Clamping to [-7, 7] | Rarely clips in practice (scales to actual range) |

### API

```c
// Quantize to TURBO2 format
void sm2_kv_turbo2_quantize(
    float* k_out, float* k_scale_out,      // Output: quantized K + per-channel scales
    float* v_out, float* v_scale_out,       // Output: quantized V + per-token scales
    const float* k_in, const float* v_in,   // Input: float32 KV
    int n_kv_heads, int head_dim, int n_tokens
);

// Dequantize from TURBO2 format
void sm2_kv_turbo2_dequant(
    float* out,              // Output: float32
    const float* qdata,      // Input: quantized values
    const float* scales,     // Input: scales (per-channel for K, per-token for V)
    int n_kv_heads, int head_dim, int n_tokens,
    int is_k               // 1 for K (per-channel), 0 for V (per-token)
);
```

### Memory Layout (Quantized)

```
K cache (per layer):
  [quantized: n_kv_heads * n_tokens * head_dim]  (int8-like, values -7..7)
  [scales: n_kv_heads * head_dim]               (float32)

V cache (per layer):
  [quantized: n_kv_heads * n_tokens * head_dim] (int8-like, values -7..7)
  [scales: n_tokens]                             (float32)
```
