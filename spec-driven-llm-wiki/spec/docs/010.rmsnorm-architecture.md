# RMSNorm Architecture Documentation

## Overview

RMSNorm (Root Mean Square Normalization) is a computationally cheaper alternative to LayerNorm, used extensively in SmolLM2. This document covers the mathematical foundation, implementation details, numerical stability considerations, and buffer management in the codebase.

---

## Mathematical Foundation

### RMSNorm Formula

```
RMS(x) = sqrt(sum(x[i]^2) / n + eps)
output[i] = (x[i] / RMS(x)) * weight[i]
```

**Step-by-step computation:**
1. Compute sum of squares: `sum_sq = sum(x[i]^2)` for i in [0, n)
2. Compute RMS: `rms = sqrt(sum_sq / n + eps)`
3. Compute scale: `scale = 1.0f / rms`
4. Apply normalization with weight: `output[i] = x[i] * scale * weight[i]`

### Epsilon Value

Epsilon is set to `1e-5f` (0.00001) across all SmolLM2 variants:

```c
// From sm2_specs[] in include/smollm2.h
{ SM2_135M,  30,  576, 1536,  9,  3, 64, 49152, 8192, 1e-5f, ... },
{ SM2_360M,  32,  960, 2560, 15,  5, 64, 49152, 8192, 1e-5f, ... },
{ SM2_1700M, 24, 2048, 8192, 32, 32, 64, 49152, 8192, 1e-5f, ... },
```

**Purpose of epsilon:** Prevents division by zero when RMS approaches zero. With `1e-5f`, the minimum RMS value is `sqrt(1e-5) = 0.00316`, ensuring numerical stability.

### Weight Application

All layer norm weights are learnable parameters stored in F16 format:

```c
// Weight storage (from smollm2.h)
uint16_t* input_layernorm;           // [n_layers * dim] of F16
uint16_t* post_attention_layernorm;  // [n_layers * dim] of F16
uint16_t* final_norm;               // [dim] of F16 (shared, not per-layer)
```

Weights are converted from F16 to float during computation:
```c
uint16_t w = model->input_layernorm[ln_off + i];
xb_out[i] = (x_in[i] / rms) * sm2_f16_to_float(w);
```

| Aspect | RMSNorm | LayerNorm |
|--------|---------|-----------|
| Mean centering | No | Yes |
| Normalization | Only by RMS | By RMS after centering |
| Computational cost | O(n) | O(2n) |
| Parameter count | n (weight only) | 2n (weight + bias) |
| Typical eps | 1e-5 | 1e-5 |

**Key insight**: RMSNorm omits mean subtraction, making it ~10% faster while maintaining comparable performance. The formula simplifies to normalizing by the root mean square of the input.

## Implementations in Codebase

### 1. Standalone Library (`src/sm2_rmsnorm.c`)

```c
void sm2_rmsnorm(float* out, const float* input, const float* weight, int size, float eps) {
    float sum_sq = 0.0f;
    for (int i = 0; i < size; i++) {
        sum_sq += input[i] * input[i];
    }
    
    float rms = sqrtf(sum_sq / (float)size + eps);
    float scale = 1.0f / rms;
    
    for (int i = 0; i < size; i++) {
        out[i] = input[i] * scale * weight[i];
    }
}
```

**In-place variant:**
```c
void sm2_rmsnorm_inplace(float* vec, const float* weight, int size, float eps) {
    float sum_sq = 0.0f;
    for (int i = 0; i < size; i++) {
        sum_sq += vec[i] * vec[i];
    }
    
    float rms = sqrtf(sum_sq / (float)size + eps);
    float scale = 1.0f / rms;
    
    for (int i = 0; i < size; i++) {
        vec[i] = vec[i] * scale * weight[i];
    }
}
```

                       |

                       |

+----------------------+----------------------+
| Step 5-6: RoPE + KV cache                    |
| Modify q[], k[] in-place                     |
+----------------------+----------------------+
                       |

+----------------------+----------------------+

| Read q[], write to attn_out[]                |  attn_out = attention(q, k, v)

                       |

+----------------------+----------------------+

+----------------------+----------------------+
                       |

+----------------------+----------------------+
                       |

+----------------------+----------------------+

+----------------------+----------------------+
                       |

+----------------------+----------------------+

### Scratch Buffer Usage

| Buffer | Size | Purpose |
|--------|------|---------|
| `ctx->scratch.q` | `dim` | Query projection output |
| `ctx->scratch.k` | `kv_dim` | Key projection output |
| `ctx->scratch.v` | `kv_dim` | Value projection output |
| `ctx->scratch.attn_out` | `dim` | Attention output |

## Critical Bug Analysis

### Is there a use-before-definition bug with xb_out?

**NO.** The analysis is clear:

1. Line 201: `float x_residual[DIM_MAX]` - copies x_in BEFORE any writes to xb_out
2. Lines 214-221: RMSNorm writes to xb_out (input_layernorm) - this is intentional, xb_out IS the output buffer
3. Lines 286-296: O projection OVERWRITES xb_out with attention output
4. Lines 299-302: Residual is ADDED (not replacing)
5. Lines 308-315: RMSNorm writes to xb_out (post_attention_layernorm)
6. Lines 372: FFN output + residual written to xb_out

**The ping-pong is CORRECT.** The function is designed to:
1. Read from x_in (saved separately)
2. Write intermediate results to scratch buffers (q, k, v, attn_out)
3. Accumulate final output in xb_out

### Is the epsilon correct (1e-5f matches spec)?

**YES.** All RMSNorm instances use `1e-5f`:

- Inline implementations: `+ 1e-5f`
- Spec definition in `include/smollm2.h` line 66-70: `rms_eps = 1e-5f`

```c
// From sm2_specs[] in include/smollm2.h
{ SM2_135M,  30,  576, 1536,  9,  3, 64, 49152, 8192, 1e-5f, 100000.0f, 1, 2, 0 },
{ SM2_360M,  32,  960, 2560, 15,  5, 64, 49152, 8192, 1e-5f, 100000.0f, 1, 2, 0 },
{ SM2_1700M, 24, 2048, 8192, 32, 32, 64, 49152, 8192, 1e-5f, 130000.0f, 1, 2, 0 },
```

### Are weights in F16 format being converted correctly?

**YES.** All layer norm weights are stored as F16 and converted:

```c
uint16_t w = model->input_layernorm[ln_off + i];
xb_out[i] = (x_in[i] / rms) * sm2_f16_to_float(w);
```

The `sm2_f16_to_float()` function is used consistently throughout.

## Performance Considerations

1. **Two-pass algorithm**: First pass computes RMS, second pass applies normalization
2. **Kahan summation**: Not used in RMSNorm (cumulative error is minimal for sum of squares)
3. **SIMD potential**: `sm2_rmsnorm_simd()` exists but falls back to scalar
4. **Stack allocation**: `x_residual` and `x_post_attn` use stack (DIM_MAX=2048 = 8KB each)

---

## Potential Improvements

1. **Fuse RMS computation**: Could compute scale as `rsqrteps(sum_sq)` with one pass
2. **SIMD implementation**: Add NEON/SSE variants for ARM/x86
3. **Reduce stack usage**: `x_post_attn` could use `ctx->scratch.attn_out` (already allocated)
4. **Weight dequantization**: Cache F16->float conversions if weights are reused
