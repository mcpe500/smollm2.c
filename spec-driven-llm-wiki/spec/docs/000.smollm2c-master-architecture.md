### GQA Explanation

- **Grouped Query Attention (GQA)**: Multiple query heads share each key/value head
- 135M: 9 Q heads / 3 KV heads = 3 Q heads per KV head
- 360M: 15 Q heads / 5 KV heads = 3 Q heads per KV head  
- 1.7B: 32 Q heads / 32 KV heads = full MHA (1:1 ratio)

# Part 3: FEATURES

## Core Features

### 1. Multiple Model Variants
- **SMOLLM2-135M**: 30 layers, dim 576, 9 heads (3 KV), ~135M params
- **SMOLLM2-360M**: 32 layers, dim 960, 15 heads (5 KV), ~360M params
- **SMOLLM2-1700M**: 24 layers, dim 2048, 32 heads (32 KV), ~1.7B params

### 2. Tokenization
- BPE (Byte-Pair Encoding) tokenizer
- Handles UTF-8 tokens with special byte mappings (Ġ for space, Ċ for newline)
- HuggingFace-compatible tokenizer.json format

### 3. Sampling Strategies
- Greedy decoding (temperature = 0)
- Temperature sampling
- Top-p (nucleus) sampling
- Top-k sampling
- Repetition penalty with sliding window

### 4. KV Cache Management
- Paged attention with configurable block size (16 tokens/page)
- Quantized KV cache (Q8, Q4, TURBO2)
- Multi-sequence support via page tables

### 5. Quantization Support
- **F16**: Direct float16 weights (2 bytes per value)
- **Q4_K**: 4-bit block quantization (32 elements/block)
- **Q8_0**: 8-bit quantization

### 6. Decode Layer (smollm2dl)
- Speculative decoding support
- Batch decode optimization
- Flash attention kernels
- KV quantization layer

### 7. Server Mode
- HTTP endpoint for API access
- SSE streaming for real-time output
- Request scheduler for concurrent requests
- Metrics collection

# Part 7: Memory Layout

## Weight Storage

All model weights are stored as F16 (float16):
- 1 F16 = 2 bytes
- All weight matrices stored row-major in memory

## KV Cache Storage

```
Per layer per KV head: max_seq_len x head_dim x sizeof(float)
Total KV: n_layers x n_kv_heads x max_seq_len x head_dim x 4 bytes
```

### SM2_135M KV Cache
```
30 layers x 3 KV heads x 8192 positions x 64 dim x 4 bytes
= 235,929,600 bytes (~225 MB)
```

### SM2_360M KV Cache
```
32 layers x 5 KV heads x 8192 positions x 64 dim x 4 bytes
= 335,544,320 bytes (~320 MB)
```

### SM2_1700M KV Cache
```
24 layers x 32 KV heads x 8192 positions x 64 dim x 4 bytes
= 4,025,508,864 bytes (~3.84 GB)
```

# Part 8: Complete Inference Pipeline

## Data Flow

```
Input Text
    |
    v
[Tokenizer: BPE Encode]
    |
    v
[Token IDs + BOS]
    |
    v
[Embedding Lookup: tok_embeddings[token_id]]
    |
    v
+===+===+===+===+===+===+===+===+===+===+
|            LAYER FORWARD                |
|  +----------------------------------+  |
|  | 1. RMSNorm(input)                |  |
|  | 2. Q projection (GQA aware)      |  |
|  | 3. K projection                  |  |
|  | 4. V projection                  |  |
|  | 5. RoPE (position encoding)     |  |
|  | 6. Store K/V to cache            |  |
|  | 7. Attention + KV cache         |  |
|  | 8. O projection                  |  |
|  | 9. Residual + x_residual        |  |
|  | 10. Post-attention RMSNorm       |  |
|  | 11. SwiGLU FFN (gate*up)*down   |  |
|  | 12. Residual + x_post_attn      |  |
|  +----------------------------------+  |
+===+===+===+===+===+===+===+===+===+===+

[Repeat for all layers]
    |
    v
[Final RMSNorm]
    |
    v
[Logits: @ tok_embeddings.T]
    |
    v
[Sampling: temperature, top-p, repetition penalty]
    |
    v
[Token ID]
    |
    v
[Tokenizer: BPE Decode]
    |
    v
Output Text
```

## Detailed Layer Forward (per token)

```
1. RMSNorm(x_in) --> xb_out
2. xb_out @ Q_proj.T --> q [dim]
3. xb_out @ K_proj.T --> k [kv_dim]
4. xb_out @ V_proj.T --> v [kv_dim]
5. RoPE(q, k)  [apply rotary position embedding]
6. Store k,v to kv_cache[layer] at position seq_pos
7. Attention(q, kv_cache) --> attn_out [dim]
8. attn_out @ O_proj.T --> xb_out
9. xb_out += x_residual  [residual connection]
10. RMSNorm(xb_out) --> xb_out
11. xb_out @ Gate_proj.T --> gate_hidden [hidden]
12. xb_out @ Up_proj.T --> up_hidden [hidden]
13. SiLU(gate_hidden) * up_hidden --> gate_act [hidden]
14. gate_act @ Down_proj.T --> ffn_out [dim]
15. xb_out = x_post_attn + ffn_out  [final residual]
```

# Part 11: Key Algorithms

## Kahan Summation (for numerical stability)

Used in all matmul operations to reduce float16 accumulation error:

```c
float sum = 0.0f;
float c = 0.0f;  // Compensation
for (int j = 0; j < dim; j++) {
    float w = f16_to_float(weight);
    float y = xb_out[j] * w - c;
    float t = sum + y;
    c = (t - sum) - y;
    sum = t;
}
```

## SwiGLU Activation

```
gate_out = gate(X * W_gate) * sigmoid(gate(X * W_gate)) * up(X * W_up)
output = gate_out @ W_down + residual
```

## Grouped Query Attention (GQA)

### 135M/360M (GQA):
- Query heads share Key/Value heads
- Reduces KV cache size by group ratio

### 1.7B (MHA):
- Each Q head has dedicated K/V head
- Full attention capacity

# Appendix A: USAGE

## Building

```bash
# Standard build
make

# Build CLI tool
make smollm2-cli

# Clean build artifacts
make clean

# Syntax check without full build
make check

# Help
make help
```

## Running

```bash
# Basic inference
./smollm2-cli -m model.sm2 -p "Hello, how are you?"

# Custom temperature
./smollm2-cli -m model.sm2 -p "Write a story" -t 0.8

# Greedy decoding (fastest)
./smollm2-cli -m model.sm2 -p "Hello" -t 0

# Top-p nucleus sampling
./smollm2-cli -m model.sm2 -p "Hello" -q 95

# Top-k sampling
./smollm2-cli -m model.sm2 -p "Hello" -k 50

# Repetition penalty
./smollm2-cli -m model.sm2 -p "Hello" -r 1.2

# Long output
./smollm2-cli -m model.sm2 -p "Tell me a story" -n 200
```

## CLI Options

| Option | Description | Default |
|--------|-------------|---------|
| `-m, --model` | Model file path (.sm2) | Required |
| `-p, --prompt` | Input prompt | "Hello" |
| `-n, --max-output` | Maximum tokens to generate | 50 |
| `-t, --temp` | Temperature (0=greedy) | 0.7 |
| `-q, --top-p` | Top-p nucleus sampling (0-100) | 90 |
| `-k, --top-k` | Top-k sampling (0=disabled) | 0 |
| `-r, --rep-penalty` | Repetition penalty (1.0=off) | 1.3 |

# Appendix B: .sm2 FILE FORMAT

The `.sm2` format is a custom binary format:
```
[256-byte header]
  - Magic: "SM2C001"
  - Version: 1
  - Model spec (dims, heads, etc.)
  - Tokenizer offset/size
  - Tensor index offset/size
  - Weights offset/size

[Tokenizer JSON]
[Tensor Index]
[Weight Data (F16 or quantized)]
```
