# Part 3: Memory Layout

## Weight Storage

All model weights are stored as F16 (float16):
- 1 F16 = 2 bytes
- All weight matrices stored row-major

## KV Cache Storage

```
Per layer per KV head: max_seq_len (8192) x head_dim (64) floats
Total KV: n_layers x n_kv_heads x 8192 x 64 x 4 bytes

SMOLLM2-135M Example:
30 layers x 3 KV heads x 8192 positions x 64 dim x 4 bytes
= 235,929,600 bytes (~225 MB)
```

| Buffer | Size | Purpose |
|--------|------|---------|

| xb | dim (576) | Residual buffer |

# Part 4: Complete Inference Pipeline

## Data Flow

```
Input Text
    |
    v
[Tokenizer: BPE Encode]
    |
    v
[Token IDs + BOS]
    |
    v
[Embedding Lookup: tok_embeddings[token_id]]
    |
    v
+===+===+===+===+===+===+===+===+===+===+
|            LAYER FORWARD                |
|  +----------------------------------+  |
|  | 1. RMSNorm(input)                |  |
|  | 2. Q projection                  |  |
|  | 3. K projection                  |  |
|  | 4. V projection                  |  |
|  | 5. RoPE (position encoding)     |  |
|  | 6. Store K/V to cache            |  |
|  | 7. Attention + KV cache         |  |
|  | 8. O projection                  |  |
|  | 9. Residual + x_residual        |  |
|  | 10. Post-attention RMSNorm       |  |
|  | 11. SwiGLU FFN (gate*up)*down    |  |
|  | 12. Residual + x_post_attn      |  |
|  +----------------------------------+  |
|              LAYER FORWARD                |
+===+===+===+===+===+===+===+===+===+===+

[Repeat for all 30 layers]
    |
    v
[Final RMSNorm]
    |
    v
[Logits: @ tok_embeddings.T]
    |
    v
[Sampling: temperature, top-p, repetition penalty]
    |
    v
[Token ID]
    |
    v
[Tokenizer: BPE Decode]
    |
    v
Output Text
```

## Detailed Layer Forward (per token)

```
1. RMSNorm(x_in) --> xb_out
2. xb_out @ Q_proj.T --> q [dim]
3. xb_out @ K_proj.T --> k [kv_dim]
4. xb_out @ V_proj.T --> v [kv_dim]
5. RoPE(q, k)  [apply rotary position embedding]
6. Store k,v to kv_cache[layer] at position seq_pos
7. Attention(q, kv_cache) --> attn_out [dim]
8. attn_out @ O_proj.T --> xb_out
9. xb_out += x_residual  [residual connection]
10. RMSNorm(xb_out) --> xb_out
11. xb_out @ Gate_proj.T --> gate_hidden [hidden]
12. xb_out @ Up_proj.T --> up_hidden [hidden]
13. SiLU(gate_hidden) * up_hidden --> gate_act [hidden]
14. gate_act @ Down_proj.T --> ffn_out [dim]
15. xb_out = x_post_attn + ffn_out  [final residual]
```

# Part 5: Known Issues & Bugs

## Issue 1: Token Isolation Pattern (CRITICAL - Architecture)

**Location:** `src/sm2_context.c` - `sm2_prefill()` and `sm2_decode_next()`

**Severity:** Design issue, model may underperform vs. reference

**Description:**
Each token is processed independently through all layers, starting from its embedding. The output hidden state is NOT propagated as input to subsequent layer processing for the same token. The layer loop re-embeds from `scratch.x` for each token.

**Code Pattern:**
```c
// sm2_prefill() - token loop
for (int t = 0; t < n_tokens; t++) {
    // EMBED CURRENT TOKEN into scratch.x
    embedding_lookup(ctx->scratch.x, tokens[t], ...);

    // PROCESS THIS TOKEN through all 30 layers
    for (int layer = 0; layer < model->n_layers; layer++) {
        layer_forward(ctx->scratch.xb, ctx->scratch.x, ...);
        // ...
    }
    // Token T is now done, move to T+1
}
```

**Impact:**
- Lower layers process the same token many times without progressive refinement
- Attention sees isolated queries for each token position
- Model outputs may differ from reference implementation
- Information只能在attention中传递，无法逐层向上传递

**Status:** Present in current implementation, not yet fixed

---

## Issue 2: Hardcoded Vocab Size

**Location:** `src/sm2_sampling.c:360-361`

**Severity:** Medium - portability bug

**Code:**
```c
float logits_copy[49152];
int vocab_size = 49152;
```

**Description:**
Vocab size hardcoded as `49152` instead of using `ctx->model->vocab_size`.

**Impact:**
- Works for SmolLM2 (49152 vocab)
- Would break for 360M or 1700M variants (same vocab, but poor design)
- Buffer size mismatch potential

**Status:** Code comment indicates awareness, not fixed

---

## Issue 3: Incomplete Chat Format Handling

**Location:** `src/smollm2.c:138-144`

**Severity:** Low - cosmetic issue

**Description:**
BOS token is automatically added, but im_start/im_end chat format tokens are not specially handled. The tokenizer may not correctly tokenize chat template special tokens.

**Current Behavior:**
```c
tokens[n_tokens++] = 1;  // BOS token
int n = sm2_tokenizer_encode(model->tokenizer, args->prompt, tokens + n_tokens, ...);
```

**Impact:**
- Plain text prompts work correctly
- System prompts with chat templates may have issues
- No special handling of `<|im_start|>` / `<|im_end|>` tokens

**Status:** Known limitation

---

## Issue 4: RoPE Position Tracking

**Location:** `src/sm2_context.c` - `seq_pos` variable

**Severity:** Low - verification needed

**Description:**
RoPE position encoding uses `seq_pos` which should track absolute position. In prefill, `seq_pos = t` (token index). In decode, `seq_pos = ctx->scratch.kv_cache_len`.

**Verification Needed:**
Code suggests correct, but should verify against reference implementation:
```c
// sm2_rope(q, k, head_dim, seq_pos, n_heads, n_kv_heads, rope_theta);
```

**Status:** Passes basic tests, edge cases untested

---

## Issue 5: Attention Softmax Normalization

**Location:** `src/sm2_context.c:160-175`

**Severity:** Low - math precision

**Description:**
Softmax divides attention weights by `sum_exp` (diverges if all scores = 0), but standard attention typically normalizes by `sum_exp`.

**Current code:**
```c
out[qh * head_dim + d] = sum / sum_exp;  // Divides by sum_exp
```

**Impact:**
- Works for typical attention scores
- Edge case of all-zero scores: division by zero
- Numerical precision concerns for very small/large values

**Status:** Present, unlikely to trigger in practice

# Part 6: Chat Format (im_start/im_end)

The SmolLM2 model uses HuggingFace-style chat format for multi-turn conversations.

## Token Definitions

Based on SmolLM2 tokenizer (may vary by vocab):

| Token | Token ID | Description |
|-------|----------|-------------|
| `<|im_start|>` | Varies | Start of message role turn |
| `<|im_end|>` | Varies | End of message turn |

## Chat Template Structure

```
<|im_start|>user
Hello, how are you?<|im_end|>
<|im_start|>assistant
I'm doing well! How can I help you?<|im_end|>
```

## Current Implementation

The tokenizer handles BPE encoding/decoding of these tokens automatically. No special application-level handling exists in the current smollm2.c implementation.

## Known Limitations

1. No automatic `<|im_start|>` / `<|im_end|>` injection
2. User must format prompts with chat tokens explicitly
3. BOS token (ID=1) automatically prepended

## Prefill vs Decode Loop

```
PREFILL (Batch Processing)
==========================
Input:  [T0, T1, T2, T3, ...]  (all prompt tokens)
Output: Hidden states + KV cache population

    For each token Ti in prompt:
        1. Embed(Ti) --> h
        2. For each layer L:
           - RMSNorm(h)
           - Q/K/V projections
           - RoPE(position=i)
           - Attention + KV_cache
           - SwiGLU FFN
           - h = output
        3. Store KV at position i
        4. h = next token's embedding (ISOLATED processing)


DECODE (Token-by-Token)
=======================
Input:  Last generated token (ctx->last_token)
Output: Next token (with prefix context)

    1. Embed(ctx->last_token) --> h
    2. For each layer L:
       - RMSNorm(h)
       - Q/K/V projections
       - RoPE(current_position)
       - Attention over ALL KV_cache
       - SwiGLU FFN
       - h = output
    3. Store new KV at current_position
    4. Sample from logits
    5. Return token
```

# Part 9: Key Algorithms

## Kahan Summation (for numerical stability)

Used in all matmul operations to reduce float16 accumulation error:

```c
float sum = 0.0f;
float c = 0.0f;  // Compensation
for (int j = 0; j < dim; j++) {
    float w = f16_to_float(weight);
    float y = xb_out[j] * w - c;
    float t = sum + y;
    c = (t - sum) - y;
    sum = t;
}
```

## SwiGLU Activation

```
gate_out = gate(X * W_gate) * sigmoid(gate(X * W_gate)) * up(X * W_up)
output = gate_out @ W_down + residual
```

## Grouped Query Attention (GQA)

- n_heads = 9 (query heads)
- n_kv_heads = 3 (key/value heads)
- group_size = 9 / 3 = 3

Each KV head serves 3 Q heads, reducing KV cache by 3x.

## RoPE (Rotary Position Embedding)

Applied per-head using complex rotation:
```
theta = rope_theta (100000)
freq = 1 / (theta ^ (2i/d))
```
