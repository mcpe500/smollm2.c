# 026. Quantization Architecture

## Executive Summary

This document describes the weight quantization schemes implemented in the SmolLM2 C codebase. Four quantization formats are implemented:

| Format | Bits/Value | Block Size | Scale | Accuracy | Use Case |
|--------|-----------|------------|-------|----------|----------|
| **Q8_0** | 8-bit | Global | Single | Highest | Reference/activation |
| **Q4_0** | 4-bit | Global | Single | Medium | Simple 4-bit |
| **Q4_K** | 4-bit | 32 elements | Per-block | Good | Production weight compression |
| **Q5_K** | 5-bit | 32 elements | Per-block | Best 4/5-bit | Experimental |

**Key Finding**: Q5_K is implemented but **not integrated** into the main `sm2_quant_type` enum in `smollm2.h`. All active quantization work uses F16 (no quantization) in the current inference path.

## 2. Q8_0 - 8-Bit Quantization

**File**: `src/quant/sm2_q8.c`

### 2.1 Quantization Scheme

- **Bits per value**: 8-bit signed integer (-128 to +127)
- **Block structure**: Global (entire tensor shares one scale)
- **Scale calculation**: `scale = max(|x|) / 127.0f`

### 2.2 Quantization Algorithm

```c
// Find maximum absolute value
float max_val = 0.0f;
for (int i = 0; i < n; i++) {
    float v = sm2_f16_to_float(input[i]);
    if (fabsf(v) > max_val) max_val = fabsf(v);
}

// Calculate scale
*scale = max_val / 127.0f;
if (*scale < 1e-7f) *scale = 1e-7f;

// Quantize each value
for (int i = 0; i < n; i++) {
    int q = (int)(v / (*scale));
    q = clamp(q, -127, 127);
    output[i] = (int8_t)q;
}
```

### 2.3 Dequantization

```c
for (int i = 0; i < n; i++) {
    float v = (float)input[i] * scale;
    output[i] = sm2_float_to_f16(v);
}
```

### 2.4 Storage Layout

| Component | Size | Format |
|-----------|------|--------|
| Quantized data | n bytes | int8_t |
| Scale | 4 bytes | float32 |

**Total size**: n + 4 bytes

### 2.5 Accuracy Tradeoffs

- **Precision loss**: ~0.1-0.5% relative error typical
- **Dynamic range**: Limited by single scale for entire tensor
- **Outlier sensitivity**: Large outliers can reduce precision for typical values
- **Best for**: Activations, small tensors, or when accuracy > size

## 3. Q4_0 - Simple 4-Bit Quantization

**File**: `src/quant/sm2_q4.c`

### 3.1 Quantization Scheme

- **Bits per value**: 4-bit (-8 to +7, signed nibbles)
- **Block structure**: Global (entire tensor shares one scale)
- **Packing**: 2 values per byte (nibble packing)
- **Scale calculation**: `scale = max(|x|) / 7.0f`

### 3.2 Quantization Algorithm

```c
// Find maximum absolute value
float max_val = 0.0f;
for (int i = 0; i < n; i++) {
    float v = sm2_f16_to_float(input[i]);
    if (fabsf(v) > max_val) max_val = fabsf(v);
}

*scale = max_val / 7.0f;

// Pack 2 values per byte
for (int i = 0; i < n / 2; i++) {
    int q0 = clamp((int)(v0 / scale), -7, 7);
    int q1 = clamp((int)(v1 / scale), -7, 7);
    output[i] = (uint8_t)((q0 & 0x0F) | ((q1 & 0x0F) << 4));
}
```

### 3.3 Dequantization

```c
for (int i = 0; i < n / 2; i++) {
    int q0 = (input[i] & 0x0F);
    int q1 = (input[i] >> 4) & 0x0F;
    
    // Sign extend from 4 bits
    if (q0 > 7) q0 -= 16;
    if (q1 > 7) q1 -= 16;
    
    output[2*i]   = sm2_float_to_f16((float)q0 * scale);
    output[2*i+1] = sm2_float_to_f16((float)q1 * scale);
}
```

### 3.4 Storage Layout

| Component | Size | Format |
|-----------|------|--------|
| Quantized data | n/2 bytes | 2 nibbles per byte |
| Scale | 4 bytes | float32 |

**Total size**: ceil(n/2) + 4 bytes = ~0.5n + 4 bytes

### 3.5 Accuracy Tradeoffs

- **Precision loss**: ~1-3% relative error (higher than Q8)
- **Dynamic range**: Only 15 distinct levels
- **Outlier clipping**: Values exceeding scale are clipped to [-7, 7]
- **Global scale limitation**: Poor for tensors with non-uniform value distributions
- **Best for**: Testing, simple use cases

## 4. Q4_K - Block 4-Bit Quantization

**File**: `src/quant/sm2_q4k.c`

### 4.1 Quantization Scheme

- **Bits per value**: 4-bit (-8 to +7, signed nibbles)
- **Block structure**: 32 elements per block, each block has its own scale
- **Packing**: 2 values per byte (nibble packing)
- **Scale calculation**: `scale = max(|x| in block) / 7.0f`

### 4.2 Quantization Algorithm

```c
#define Q4K_BLOCK_SIZE 32

int n_blocks = (rows * cols + Q4K_BLOCK_SIZE - 1) / Q4K_BLOCK_SIZE;

for (int blk = 0; blk < n_blocks; blk++) {
    // Find max in this block
    float max_val = 0.0f;
    for (int i = start; i < end; i++) {
        float v = sm2_f16_to_float(input[i]);
        max_val = fmax(max_val, fabsf(v));
    }
    
    float scale = max_val / 7.0f;
    scales[blk] = scale;
    zeros[blk] = 0.0f;  // Symmetric quantization
    
    // Quantize block
    for (int i = start; i < end; i++) {
        int idx = (i - start) / 2;
        int q = clamp((int)(v / scale), -7, 7);
        
        if ((i - start) % 2 == 0) {
            output[blk * 16 + idx] = (uint8_t)(q & 0x0F);
        } else {
            output[blk * 16 + idx] |= (uint8_t)((q & 0x0F) << 4);
        }
    }
}
```

### 4.3 Dequantization

```c
for (int blk = 0; blk < n_blocks; blk++) {
    float scale = scales[blk];
    int start = blk * Q4K_BLOCK_SIZE;
    
    for (int i = 0; i < Q4K_BLOCK_SIZE; i++) {
        int idx = i / 2;
        int shift = (i % 2) * 4;
        
        int q = (input[blk * 16 + idx] >> shift) & 0x0F;
        if (q > 7) q -= 16;  // Sign extend
        
        output[start + i] = sm2_float_to_f16((float)q * scale);
    }
}
```

### 4.4 Storage Layout

| Component | Size | Format |
|-----------|------|--------|
| Quantized data | n/2 bytes | 2 nibbles per byte |
| Scales | n_blocks * 4 bytes | float32 |
| Zeros | n_blocks * 4 bytes | float32 (currently always 0) |

**Total size**: ceil(n/2) + n_blocks * 8 bytes

**Block overhead**: 8 bytes per 32 elements = 0.25 bytes/element
**Effective bits**: 4 + 0.25 = **4.25 bits per element**

### 4.5 Accuracy Tradeoffs

- **Precision loss**: ~0.5-2% relative error (better than Q4_0)
- **Dynamic range**: Per-block scaling captures local value ranges
- **Outlier handling**: Better than global schemes
- **Memory overhead**: 0.25 bytes/element for scales
- **Best for**: Production weight compression with good accuracy

## 5. Q5_K - Block 5-Bit Quantization

**File**: `src/quant/sm2_q5k.c`

### 5.1 Quantization Scheme

| Property | Value |
|----------|-------|
| Bits per value | 5-bit signed integer (-16 to +15) |
| Block size | 32 elements |
| Quantization levels | 31 (symmetric around 0) |
| Scale calculation | `scale = max(|x| in block) / 15.0f` |
| Packing | 5-bit values span byte boundaries |

### 5.3 Bit Packing Detail

The 5-bit packing is more complex than nibble-based schemes:

```
32 values × 5 bits = 160 bits = 20 bytes per block
```

The packing uses variable bit positions per value:

```c
// Position calculation for value i in block:
// byte_idx = (i * 5) / 8
// bit_shift = (i * 5) % 8

// Value 0: byte 0, bits 0-4 (shift 0)
// Value 1: byte 0, bits 5-9 (shift 5)
// Value 2: byte 1, bits 2-6 (shift 2) <- spans byte boundary
// Value 3: byte 1, bits 7-11 (shift 7) <- spans byte boundary
// ...
```

This creates a running overlap pattern where values at certain positions span two bytes.

### 5.4 Quantization Algorithm

```c
#define Q5K_BLOCK_SIZE 32

for (int blk = 0; blk < n_blocks; blk++) {
    float max_val = 0.0f;
    for (int i = start; i < end; i++) {
        float v = sm2_f16_to_float(input[i]);
        max_val = fmax(max_val, fabsf(v));
    }
    
    float scale = max_val / 15.0f;  // 5-bit range: -15..15
    scales[blk] = scale;
    
    // Pack 5-bit values into bytes
    // 32 values * 5 bits = 160 bits = 20 bytes
    for (int i = 0; i < end - start; i++) {
        int q = clamp((int)(v / scale), -15, 15);
        
        int byte_idx = (i * 5) / 8;
        int bit_shift = (i * 5) % 8;
        
        uint16_t val = (uint16_t)(q & 0x1F);
        output[blk * 20 + byte_idx] |= (uint8_t)(val << bit_shift);
        if (bit_shift > 3) {
            output[blk * 20 + byte_idx + 1] |= (uint8_t)(val >> (8 - bit_shift));
        }
    }
}
```

### 5.5 Dequantization

```c
for (int blk = 0; blk < n_blocks; blk++) {
    float scale = scales[blk];
    
    for (int i = 0; i < Q5K_BLOCK_SIZE; i++) {
        int byte_idx = (i * 5) / 8;
        int bit_shift = (i * 5) % 8;
        
        int q = (input[blk * 20 + byte_idx] >> bit_shift) & 0x1F;
        if (bit_shift > 3) {
            q |= (input[blk * 20 + byte_idx + 1] << (8 - bit_shift)) & 0x1F;
        }
        
        if (q > 15) q -= 32;  // Sign extend
        
        output[blk * Q5K_BLOCK_SIZE + i] = sm2_float_to_f16((float)q * scale);
    }
}
```

### 5.5 Storage Layout

| Component | Size | Format |
|-----------|------|--------|
| Quantized data | 20 bytes per block | 32 * 5 bits packed |
| Scales | n_blocks * 4 bytes | float32 |

**Total size**: n_blocks * 24 bytes

**Block overhead**: 4 bytes per 32 elements = 0.125 bytes/element
**Effective bits**: 5 + 0.125 = **5.125 bits per element**

### 5.6 Accuracy Tradeoffs

- **Precision loss**: ~0.3-1.5% relative error (better than Q4_K)
- **Dynamic range**: 31 distinct levels vs 15 for Q4_K
- **Memory cost**: ~20% larger than Q4_K
- **Best for**: When Q4_K precision is insufficient but Q8 overhead is too high

### 5.7 Q5_K vs Q4_K Comparison

| Aspect | Q4_K | Q5_K | Advantage |
|--------|------|------|-----------|
| Quantization levels | 15 | 31 | Q5_K (2x more levels) |
| Precision per level | Coarser | Finer | Q5_K |
| Storage overhead | 0.25 bytes/elem | 0.125 bytes/elem | Q5_K (lower %) |
| Effective bits | 4.25 | 5.125 | Q5_K |
| Typical relative error | 0.5-2% | 0.3-1.5% | Q5_K |
| Compression vs F16 | 3.88x | 2.67x | Q4_K |

**When to use Q5_K over Q4_K**:
- Layer outputs show precision degradation with Q4_K
- Critical weight matrices (e.g., attention projection) need better precision
- Memory constraints allow ~20% more storage

**When to use Q4_K**:
- Aggressive compression is priority
- Model size on disk is the bottleneck
- Quality degradation is acceptable for the use case

## 6. Comparison Summary

### 6.1 Storage Efficiency

| Format | Raw Size (n=1024) | Quantized Size | Compression |
|--------|-------------------|----------------|-------------|
| F16 | 2048 bytes | - | 1x |
| Q8_0 | 2048 bytes | 1028 bytes | 2x |
| Q4_0 | 2048 bytes | 516 bytes | 3.97x |
| Q4_K | 2048 bytes | 528 bytes | 3.88x |
| Q5_K | 2048 bytes | 768 bytes | 2.67x |

### 6.2 Accuracy Ranking

1. **Q8_0** - Highest accuracy, 2x compression
2. **Q5_K** - Good accuracy, 2.67x compression
3. **Q4_K** - Moderate accuracy, 3.88x compression
4. **Q4_0** - Lower accuracy, 3.97x compression
