## Format Details

### HuggingFace Safetensors
- **Format**: BF16 (brain float 16)
- **Shape**: [49152, 576]
- **Data offset**: 30536 bytes (after header)
- **File**: `smollm2-135m.safetensors` (256.6 MB)

### Our .sm2 Format
- **Format**: F16 (IEEE float 16) - converted from BF16
- **Shape**: [49152, 576]
- **Weights offset**: 1179115 bytes (after header + tokenizer)
- **File**: `smollm2-135m-v2.sm2` (257.7 MB)

## Conversion Verification

The conversion script (`tools/smollm2-convert.py`) correctly converts BF16 to F16:
- BF16: sign(1) + exp(8) + mantissa(7) = 16 bits
- F16: sign(1) + exp(5) + mantissa(10) = 16 bits

The conversion preserves all significant bits of the mantissa (7 bits in BF16 become the top 7 bits of the 10-bit F16 mantissa, with the bottom 3 bits set to 0).

## Conclusion

**YES - We are loading the same weights that Ollama uses.**

Since Ollama converts from HuggingFace's safetensors format to GGUF, and our `.sm2` format also converts from the same safetensors source, both should produce identical results (modulo any quantization that Ollama might apply).

The embedding matrices are verified to be bit-exact between:
1. Original HuggingFace safetensors
2. Our converted .sm2 binary format

This confirms our weight loading is correct and compatible with the reference implementation.
