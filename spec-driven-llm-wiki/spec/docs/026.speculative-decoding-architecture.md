# 026: Speculative Decoding Architecture

> Draft-verifier pattern for 2-4x throughput gains with lossless quality.

---

## 0. Overview

Speculative decoding accelerates autoregressive inference by using a smaller "draft" model to propose token sequences that a larger "target" model verifies in parallel. This approach achieves:

- **2-4x speedup** when acceptance rate exceeds 80%
- **Lossless quality** - output is identical to standard autoregressive decoding
- **No approximation** - no quality degradation from distillation or quantization

---

## 1. Algorithm: Draft-Verifier Pattern

```
┌─────────────────────────────────────────────────────────────┐
│ SPECULATIVE DECODE STEP (K=4 draft tokens)                  │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  STEP 1: DRAFT PHASE (small model: 135M)                    │
│  ─────────────────────────────────────────────────────      │
│  Draft model generates K tokens autoregressively:           │
│                                                              │
│    token[0] → 135M → token[1]                               │
│                ↓                                            │
│            token[1] → 135M → token[2]                       │
│                        ↓                                    │
│                    token[2] → 135M → token[3]               │
│                                ↓                            │
│                            token[3] → 135M → token[4]       │
│                                                              │
│  Draft tokens: [t₁, t₂, t₃, t₄]                             │
│                                                              │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  STEP 2: VERIFY PHASE (large model: 360M/1.7B)              │
│  ─────────────────────────────────────────────────────      │
│  Target model prefill + verifies all K tokens at once:       │
│                                                              │
│    prefill([t₁, t₂, t₃, t₄])                                │
│    for each position i:                                      │
│        if target.argmax == draft[i]: accept++                │
│        else: stop accepting                                  │
│                                                              │
│  Example: Target predicts [t₁, t₂, x, ...]                   │
│           Draft was      [t₁, t₂, t₃, t₄]                   │
│           → Accept [t₁, t₂], sample from target for position 3
│                                                              │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  STEP 3: OUTPUT                                             │
│  ─────────────────────────────────────────────────────      │
│  Return: accepted draft token or newly sampled token         │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

## 2. Data Structures

```c
typedef struct {
    sm2_model* draft_model;     // Small model (135M)
    sm2_model* target_model;    // Large model (360M/1.7B)
    sm2_context* draft_ctx;     // Separate context for draft
    sm2_context* target_ctx;    // Separate context for target
    int draft_tokens;           // K = 2, 4, or 8 (default: 4)
    float accept_threshold;     // Acceptance threshold (unused?)
    int n_accepted;            // Running accept count
    int n_rejected;             // Running reject count
} sm2_spec_dec;
```

### Key Design Decisions

1. **Separate contexts**: Each model has its own `sm2_context` with independent:
   - KV caches (important - different model architectures)
   - Scratch buffers
   - Position tracking

2. **Static K**: Default is K=4. 2 is more conservative, 8 risks rejection waste.

## 3. Phase Implementation

### 3.1 Draft Phase (`sm2_spec_draft`)

```c
int sm2_spec_draft(sm2_spec_dec* spec, int* out_tokens) {
    sm2_context* ctx = spec->draft_ctx;
    
    for (int i = 0; i < spec->draft_tokens; i++) {
        int token;
        int ok = sm2_decode_next(ctx, &token);  // Standard autoregressive
        if (ok != 0) return i;                   // Early exit on error
        out_tokens[i] = token;
        
        if (token == 2) break;                   // EOS stops early
    }
    return spec->draft_tokens;
}
```

**Properties**:
- Uses standard `sm2_decode_next()` for each token
- Each token updates draft's KV cache sequentially
- Early termination on EOS token

### 3.2 Verify Phase (`sm2_spec_verify`)

```c
int sm2_spec_verify(sm2_spec_dec* spec, const int* draft_tokens, int n_tokens) {
    // Step 1: Prefill target with all draft tokens (parallel computation)
    int ok = sm2_prefill(spec->target_ctx, draft_tokens, n_tokens);
    if (ok != 0) return 0;
    
    // Step 2: Check each position
    int n_accepted = 0;
    
    for (int i = 0; i < n_tokens; i++) {
        // Find argmax of target logits
        float max_logit = spec->target_ctx->scratch.logits[0];
        int max_idx = 0;
        for (int j = 1; j < vocab_size; j++) {
            if (spec->target_ctx->scratch.logits[j] > max_logit) {
                max_logit = spec->target_ctx->scratch.logits[j];
                max_idx = j;
            }
        }
        
        // Accept if target agrees with draft
        if (max_idx == draft_tokens[i]) {
            n_accepted++;
        } else {
            break;  // First mismatch - stop accepting
        }
        
        // Decode one step to get next logits ready
        int dummy_token;
        sm2_decode_next(spec->target_ctx, &dummy_token);
    }
    
    spec->n_accepted += n_accepted;
    spec->n_rejected += (n_tokens - n_accepted);
    
    return n_accepted;
}
```

**Properties**:
- Single `sm2_prefill()` call processes all K tokens in parallel
- Target's KV cache grows by K positions after verification
- Greedy verification (uses argmax, not sampling)
- Early stopping on first mismatch

### 3.3 Full Step (`sm2_spec_decode_step`)

```c
int sm2_spec_decode_step(sm2_spec_dec* spec, int* out_token) {
    // Generate K draft tokens
    int draft_tokens[8];
    int n_draft = sm2_spec_draft(spec, draft_tokens);
    
    if (n_draft == 0) {
        *out_token = 2;  // EOS
        return 0;
    }
    
    // Verify with target model
    int n_accepted = sm2_spec_verify(spec, draft_tokens, n_draft);
    
    // Return accepted token or sample new one
    if (n_accepted > 0) {
        *out_token = draft_tokens[n_accepted - 1];
    } else {
        // All rejected - sample from target distribution
        *out_token = sm2_sample_token(
            spec->target_ctx->scratch.logits,
            &spec->target_ctx->params,
            &spec->target_ctx->rng_state,
            spec->target_ctx
        );
    }
    
    return 0;
}
```

## 4. Acceptance Criteria

The verification uses a simple greedy criterion:

| Condition | Action |
|-----------|--------|
| `target.argmax == draft[i]` | Accept draft token, continue |
| `target.argmax != draft[i]` | Stop, sample from target distribution |

### Acceptance Rate Formula

```
acceptance_rate = n_accepted / (n_accepted + n_rejected)
```

### Performance Thresholds

| Acceptance Rate | Speedup | Notes |
|-----------------|---------|-------|
| > 90% | ~3-4x | Excellent, near-optimal |
| 80-90% | ~2-3x | Good, typical for similar models |
| 60-80% | ~1.5-2x | Marginal, draft too different |
| < 60% | ~1x or worse | Harmful, use standard decode |

### Factors Affecting Acceptance

1. **Model similarity**: 135M → 360M has higher acceptance than 135M → 1.7B
2. **Token type**: Common tokens (spaces, punctuation) have higher acceptance
3. **Position**: Early tokens in draft have higher acceptance (confident predictions)
4. **Temperature**: Lower temperature = more peaked distributions = higher acceptance

## 5. Memory Layout

```
sm2_spec_dec (speculative decoder)
├── draft_model (135M)
│   ├── weights: ~150MB
│   └── KV cache: n_layers × n_kv_heads × max_seq × head_dim
│
└── target_model (360M)
    ├── weights: ~400MB
    └── KV cache: n_layers × n_kv_heads × max_seq × head_dim

Total: ~550MB for models + KV caches (varies by max_seq)
```

### KV Cache Independence

Critical: The draft and target have separate KV caches because:
1. Different layer counts (30 vs 32 for 135M vs 360M)
2. Different hidden dimensions (576 vs 960)
3. Different GQA configurations

The verification phase prefill builds up the target's KV cache correctly.

## 7. Comparison with Other Decode Strategies

| Strategy | Throughput | Memory | Quality | Use Case |
|----------|------------|--------|---------|----------|
| **Speculative (this)** | High (2-4x) | 2x models | Lossless | GPU/multi-core |
| Standard autoregressive | Baseline | 1x | Exact | Any |
| Batch decode | Medium | Shared | Exact | Multi-request |
| Flash decode | High | Optimized | Approx | Memory-limited |

## 8. Potential Improvements

1. **Adaptive K**: Start with K=2, increase to 8 as acceptance rate increases
2. **Sample verification**: Instead of greedy argmax, sample from target distribution
3. **N-gram matching**: Accept multiple tokens if N-gram appears in draft chain
4. **Target-guided draft**: Use target's logits to guide draft generation
