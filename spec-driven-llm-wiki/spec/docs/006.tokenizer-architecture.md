## 1. Tokenizer Loading from .sm2 File

### File Layout

The `.sm2` file is laid out as follows:

| Region               | Offset  | Size        |
|----------------------|---------|-------------|
| File header          | 0       | 256 bytes   |
| Tokenizer binary blob| 256     | 1,178,859 bytes |
| Tensor index         | varies  | varies      |
| Weights              | varies  | varies      |

The file header (defined in `include/smollm2.h` as `sm2_file_header`) contains two fields that tell us where the tokenizer lives:

```c
uint64_t tokenizer_offset;  // absolute byte offset from start of file
uint64_t tokenizer_size;    // size in bytes
```

For SmolLM2, `tokenizer_offset = 256` and `tokenizer_size = 1,178,859`.

### Loading Process (`sm2_load_tokenizer_from_sm2`)

```c
int sm2_load_tokenizer_from_sm2(sm2_tokenizer* tok, FILE* f, uint64_t offset, uint64_t size)
```

1. **Seek** to `offset` bytes from the start of the file.
2. **Allocate** a temporary buffer of `size` bytes and read the entire blob in one `fread()` call.
3. **Allocate** the in-memory vocab arrays:
   - `tok->tokens` — array of 49,152 `char*` pointers (initialized to NULL)
   - `tok->token_to_id` — array of 49,152 `int` (initialized to 0)
4. **Initialize** `byte_to_token[256]` to identity mapping (`byte[i] = i`).
5. **Parse** the binary blob in two passes (described below).
6. **Free** the temporary buffer and return.

## 2. Vocab Structure

### Binary Format

The tokenizer blob encodes **vocab first**, then **merges**:

```
[token 0][token 1]...[token 49151][num_merges (4 bytes)][merge 0][merge 1]...[merge N]
```

Each token entry is:

```
[4-byte little-endian length][len bytes of UTF-8 token data]
```

Total vocab: **49,152 entries**.

### Parsing Loop

```c
uint32_t pos = 0;
for (int i = 0; i < tok->vocab_size && pos < size; i++) {
    uint32_t len = *(uint32_t*)(data + pos);  // read 4-byte little-endian length
    pos += 4;
    if (len > 0 && pos + len <= size) {
        char* token = malloc(len + 1);
        memcpy(token, data + pos, len);
        token[len] = '\0';
        tok->tokens[i] = token;         // id-to-string: tokens[id] = string
        tok->token_to_id[i] = i;         // string-to-id: token_to_id[string] = id
        // ... also update byte_to_token mapping (see Section 3)
        pos += len;
    }
}
```

Key property: **token ID == array index**. The `.sm2` format does not store an explicit string-to-id lookup table; it uses positional encoding. `token_to_id[i]` is always set to `i`, so the inverse mapping is trivial. To look up a token ID for a given string, the code falls back to linear search over the `tokens` array (see `find_token_id_by_string` below).

## 3. Byte-to-Token Mapping

### Purpose

Byte-level BPE tokenizers (like SmolLM2's) need a way to convert raw bytes (0–255) into vocabulary tokens. Not every byte has a direct single-token representation — many byte values are only representable as multi-byte UTF-8 sequences. The `byte_to_token[256]` array bridges this gap.

### Structure

```c
// In sm2_tokenizer struct (include/smollm2.h)
int byte_to_token[256];
```

Maps a raw byte value (0–255) to the **vocab token ID** that represents that byte.

### Initialization

The array starts as the **identity mapping**: `byte_to_token[i] = i`.

### Updates During Vocab Loading

During the vocab parsing loop, two kinds of entries override this default:

**Rule 1 — Single-byte tokens** (len == 1):
```c
if (len == 1) {
    unsigned char byte_val = (unsigned char)token[0];
    tok->byte_to_token[byte_val] = i;   // override: raw byte -> vocab ID
}
```
If the vocab contains a token that is exactly one byte long (e.g., ASCII characters), the corresponding entry in `byte_to_token` is updated to point to that token's ID. This handles the common case where ASCII characters have dedicated vocab entries.

**Rule 2 — Space marker `Ġ` (len == 2, bytes 0xC4 0xA0)**:
```c
if (len == 2 && (unsigned char)token[0] == 0xC4 && (unsigned char)token[1] == 0xA0) {
    tok->byte_to_token[32] = i;         // ASCII space (32) -> Ġ token
}
```
SmolLM2 uses the Unicode character `Ġ` (U+0120, encoded as UTF-8 bytes `0xC4 0xA0`) as a special prefix token that indicates **"space before this word"**. This maps the raw space byte (32) to the vocab token for `Ġ`.

### Usage in Encoding

During `sm2_tokenizer_encode`, when a space character is encountered in the pre-tokenization step, the encoder does NOT fall back to the HuggingFace `ByteLevel` behavior of emitting individual UTF-8 bytes for the space character. Instead, it uses:

```c
int space_token = tok->byte_to_token[32];  // space byte -> Ġ token
ids[n++] = space_token;
```

This is a **critical difference**: a single space becomes **one token** (the `Ġ` token), not 1–4 separate byte tokens.

### Lookup Function

```c
int sm2_tokenizer_byte_to_token(sm2_tokenizer* tok, unsigned char byte_val) {
    if (!tok || byte_val >= 256) return byte_val;
    return tok->byte_to_token[byte_val];
}
```

## 4. Merges: Storage, Normalization, and Usage

### Storage Format

After all 49,152 tokens, the binary blob contains:

```
[4-byte num_merges][merge 0][merge 1]...[merge N-1]
```

Each merge entry is:

```
[4-byte length][len bytes of merge string]
```

### The Merge Normalization Fix (Critical)

**Source format**: The HuggingFace `tokenizer.json` stores merges as **two tokens separated by a space**, for example:
```
"Ġ h"
```
This represents the merge of the `Ġ` token with the `h` token.

**Required format for BPE**: The BPE algorithm needs to concatenate token strings directly, so the merge must be stored as:
```
"Ġh"
```
(with no space).

**The fix** — applied during loading:

```c
// Normalize merge: remove spaces used as separators between tokens
// tokenizer.json stores merges as "token1 token2", we need "token1token2"
{
    char* src = merge;
    char* dst = merge;
    while (*src) {
        if (*src != ' ') {
            *dst++ = *src;
        }
        src++;
    }
    *dst = '\0';
}
```

This **in-place** transformation strips all space characters from the merge string. The result is a concatenated token pair that can be directly matched against concatenated segment strings during BPE merging.

**Why this matters**: If the space is not removed, the BPE lookup for `"Ġh"` in the merges table would search for `"Ġ h"` (with a space), and would never find a match. The vocabulary contains `"Ġh"` as a single token string, but the merge table would have `"Ġ h"` — a mismatch that would break all multi-token merges.

### Why Merges Use Spaces in tokenizer.json

HuggingFace's tokenizer.json uses space as a human-readable separator because merge keys are pairs of subword tokens. For example, the merge that combines `Ġ` and `h` into `Ġh` is stored as `"Ġ h"` in the JSON. The C implementation strips the space to create the actual concatenated token string `"Ġh"`.

### Merge Rank (Priority)

Merges are stored in **priority order** — merge at index 0 has the highest frequency (most preferred), and higher indices are less preferred. During BPE encoding, the algorithm always applies the **lowest-ranked** (most preferred) merge first.

## 5. Pre-tokenization

### The `pre_tokenize` Function

Pre-tokenization splits raw input text into a sequence of `token_piece` structs:

```c
typedef enum {
    TOKEN_PIECE_WORD,      // Regular word text
    TOKEN_PIECE_SPACE,     // Whitespace (will become Ġ prefix)
} token_piece_type;

typedef struct {
    token_piece_type type;
    const char* text;
    int len;
} token_piece;
```

### Algorithm

```c
static int pre_tokenize(const char* text, token_piece* pieces, int max_pieces) {
    const char* p = text;
    while (*p && n < max_pieces - 1) {
        if (is_whitespace(*p)) {
            // Each whitespace character becomes its own piece
            pieces[n].type = TOKEN_PIECE_SPACE;
            pieces[n].text = p;
            pieces[n].len = 1;    // exactly 1 byte (space, newline, tab, etc.)
            p++;
            n++;
        } else {
            // Collect consecutive non-whitespace characters as a word
            const char* start = p;
            while (*p && !is_whitespace(*p)) p++;
            pieces[n].type = TOKEN_PIECE_WORD;
            pieces[n].text = start;
            pieces[n].len = (int)(p - start);
            n++;
        }
    }
    return n;
}
```

### Special Handling of `Ġ` (0xC4 0xA0)

The UTF-8 encoding of `Ġ` (U+0120) is the two-byte sequence `0xC4 0xA0`. This token appears **in the vocabulary** and represents **"a space before this token"**.

When pre-tokenization encounters a space character, it outputs a `TOKEN_PIECE_SPACE` piece. During encoding, this space is converted to the `Ġ` token via `byte_to_token[32]`. The subsequent word token is then BPE-encoded normally. When the word tokens and the `Ġ` token are decoded together, the `Ġ` bytes `0xC4 0xA0` are output as-is, which renders as a space followed by the word.

Example: the text `" hello"` (space + hello) becomes:
1. Pre-tokenize: `[SPACE piece]`, `[WORD "hello"]`
2. Encode SPACE: `Ġ` token (vocab ID for `Ġ`)
3. Encode hello: via BPE → token IDs
4. Output sequence: `[Ġ_token, ...hello_token_ids...]`

### Whitespace Definition

```c
static int is_whitespace(char c) {
    return c == ' ' || c == '\n' || c == '\r' || c == '\t' || c == '\v';
}
```

All five common whitespace characters trigger `TOKEN_PIECE_SPACE` and become `Ġ` tokens. Newlines, tabs, and carriage returns each produce their own `Ġ` token.

## 6. BPE Algorithm

### Entry Point: `bpe_encode_word`

```c
static int bpe_encode_word(sm2_tokenizer* tok, const char* word, int* ids, int max_len)
```

### Step-by-Step Walkthrough

#### Step 0: Fallback for Empty/Missing Vocab

If `tok->merges` is NULL or `tok->num_merges == 0`:
```c
for (int i = 0; word[i] && n < max_len; i++) {
    unsigned char b = (unsigned char)word[i];
    ids[n++] = b;          // raw byte values as token IDs
}
return n;
```
Each character byte is emitted as its own ID. This is the **byte-level fallback**.

#### Step 1: Base Segmentation

Each character of the input word becomes a separate segment:

```c
for (int i = 0; i < word_len; i++) {
    unsigned char byte_val = (unsigned char)word[i];
    int token_id = find_token_id_by_string(tok, (const char*)&byte_val, 1);
    if (token_id < 0) token_id = byte_val;  // fallback to raw byte

    segments[n_segs] = token_id;             // final output IDs
    seg_strs[n_segs] = malloc(2);
    seg_strs[n_segs][0] = (char)byte_val;    // UTF-8 string for this segment
    seg_strs[n_segs][1] = '\0';
    n_segs++;
}
```

Two parallel arrays are maintained:
- `segments[i]` — the token ID for segment `i`
- `seg_strs[i]` — the actual UTF-8 string that comprises segment `i`

The lookup uses `find_token_id_by_string`, which performs a linear scan of the vocab:
```c
static int find_token_id_by_string(sm2_tokenizer* tok, const char* s, int s_len) {
    for (int i = 0; i < tok->vocab_size; i++) {
        if (tok->tokens[i]) {
            int tok_len = strlen(tok->tokens[i]);
            if (tok_len == s_len && memcmp(tok->tokens[i], s, s_len) == 0) {
                return i;
            }
        }
    }
    return -1;
}
```

#### Step 2: Iterative Merging

The core BPE loop continues until no more merges are possible:

```c
while (iterations < max_iterations && n_segs > 1) {
    int best_rank = -1;
    int best_idx = -1;

    // 2a: Find the best pair (lowest rank = highest priority merge)
    for (int i = 0; i < n_segs - 1; i++) {
        // Build concatenated string of adjacent segments
        char* pair = malloc(len1 + len2 + 1);
        memcpy(pair, seg_strs[i], len1);
        memcpy(pair + len1, seg_strs[i + 1], len2);
        pair[len1 + len2] = '\0';

        // Search for this pair in the merges table
        int rank = -1;
        for (int m = 0; m < tok->num_merges; m++) {
            if (strcmp(tok->merges[m], pair) == 0) {
                rank = m;    // lower m = higher priority
                break;
            }
        }

        if (rank >= 0 && (best_rank < 0 || rank < best_rank)) {
            best_rank = rank;
            best_idx = i;
        }
    }

    if (best_idx < 0) break;  // No mergeable pairs found

    // 2b: Build merged string
    char* merged = malloc(merged_len + 1);
    strcpy(merged, seg_strs[best_idx]);
    strcat(merged, seg_strs[best_idx + 1]);

    // 2c: Look up merged string in vocab
    int merged_id = find_token_id_by_string(tok, merged, merged_len);
    if (merged_id < 0) break;  // Merged string not in vocab

    // 2d: Apply merge in-place
    segments[best_idx] = merged_id;
    free(seg_strs[best_idx]);
    seg_strs[best_idx] = merged;

    // 2e: Shift remaining segments left
    for (int i = best_idx + 1; i < n_segs - 1; i++) {
        segments[i] = segments[i + 1];
        seg_strs[i] = seg_strs[i + 1];
    }
    n_segs--;
}
```

**Key properties**:
- After each merge, only ONE new token replaces TWO adjacent tokens.
- The algorithm greedily applies the best (lowest-ranked) merge at each step.
- After a merge, the search restarts from the beginning of the segment list, so a newly created segment can immediately participate in another merge.

#### Step 3: Output

```c
for (int i = 0; i < n_segs && n < max_len; i++) {
    ids[n++] = segments[i];
}
```

### Byte-Level Fallback Behavior

When no merges apply (either because there are no merges, or because no pair of adjacent segments forms a known merge):

- Each character is emitted as a separate token ID.
- For ASCII characters that have vocab entries, those token IDs are used.
- For multi-byte UTF-8 characters, the individual bytes are emitted as their raw byte values.
- The `find_token_id_by_string` call with length 1 looks for the single-byte string in the vocab; if not found, the raw byte value is used as the token ID.

## 7. Decode

### Entry Point: `sm2_tokenizer_decode`

```c
char* sm2_tokenizer_decode(sm2_tokenizer* tok, const int* ids, int n_ids)
```

### Process

```c
size_t pos = 0;
for (int i = 0; i < n_ids && pos < out_capacity - 1; i++) {
    int id = ids[i];

    // Special token handling (see Section 8)
    if (id == 0) { break; }                   // <|endoftext|> - stop
    else if (id == 1) { continue; }          // <|im_start|> - skip
    else if (id == 2) { break; }              // <|im_end|> - end of message

    // Regular token
    else if (id >= 0 && id < tok->vocab_size) {
        if (tok->tokens && tok->tokens[id]) {
            const char* token_str = tok->tokens[id];
            size_t tok_len = strlen(token_str);
            for (size_t j = 0; j < tok_len && pos < out_capacity - 1; j++) {
                out[pos++] = token_str[j];    // copy UTF-8 bytes directly
            }
        }
    }
}
out[pos] = '\0';
```

### Key Observations

1. **Direct byte copy**: Token UTF-8 bytes are copied verbatim to the output buffer. There is **no byte-level detokenization** (unlike HuggingFace's `ByteLevel` tokenizer which converts bytes back to Unicode characters). The `Ġ` token's UTF-8 bytes `0xC4 0xA0` are copied as-is, which naturally renders as a space character followed by the word in a UTF-8-aware terminal.

2. **No reversal of merges**: Decoding does not need to "undo" merges. Each token ID maps directly to its UTF-8 string representation in `tok->tokens[id]`, which is already the fully-decoded form.

3. **Buffer sizing**: Output capacity is `n_ids * 8 + 1`. This assumes at most 8 bytes per token (overkill for UTF-8) and leaves room for a null terminator.

## 8. Special Tokens

### Token ID Mapping

| Token Name        | ID | Decode Behavior              | Encode Behavior        |
|-------------------|----|-------------------------------|------------------------|
| `<|endoftext|>`   | 0  | Stop processing, return       | Emitted on explicit call |
| `<|im_start|>`    | 1  | Skip (no output)              | Prepended for chat ML |
| `<|im_end|>`      | 2  | Stop processing, return       | Emitted for chat ML   |

### Encode Behavior

The tokenizer does **not** automatically prepend/append BOS/EOS tokens. Caller code is responsible for:
- Adding BOS token (ID 1) before the prompt if needed.
- Checking for EOS token (ID 2) to know when generation is complete.

### Model Spec Constants

From `include/smollm2.h`:

```c
// sm2_specs[SM2_135M]:
.bos_token_id = 1,
.eos_token_id = 2,
.pad_token_id = 0,
```

All three SmolLM2 variants (135M, 360M, 1700M) share these token IDs.

### ChatML Format

SmolLM2 uses the ChatML prompt format:

```
<|im_start|>user
Hello, how are you?<|im_end|>
<|im_start|>assistant
```

The `<|im_start|>` token (ID 1) is skipped during decode output. The `<|im_end|>` token (ID 2) signals end of the assistant's message.

## 9. End-to-End Encoding Traces

### Trace: Encoding `"hello"`

**Input**: The C string `"hello"` (5 ASCII characters).

**Pre-tokenization**: `["hello"]` — one `TOKEN_PIECE_WORD` piece.

**BPE base segmentation** (`seg_strs` state after Step 1):
```
seg 0: "h"  -> find_token_id_by_string(tok, "h", 1) -> vocab ID (e.g., 314)
seg 1: "e"  -> find_token_id_by_string(tok, "e", 1) -> vocab ID (e.g., 300)
seg 2: "l"  -> find_token_id_by_string(tok, "l", 1) -> vocab ID (e.g., 337)
seg 3: "l"  -> vocab ID (e.g., 337)
seg 4: "o"  -> find_token_id_by_string(tok, "o", 1) -> vocab ID (e.g., 362)
```

**BPE merge loop** (for each adjacent pair, check if `"h"+"e"`, `"e"+"l"`, etc. is in merges):

The merge table contains the entry `"Ġh"` at some rank (after normalization). When the text `" hello"` (with leading space) is encoded:
- Pre-tokenize: `[SPACE]`, `[hello]`
- SPACE encodes to the `Ġ` token (via `byte_to_token[32]`)
- `hello` base segments: `["h", "e", "l", "l", "o"]`
- Merge pair `"Ġ"+"h"` matches merge `"Ġh"` → creates segment `["Ġh"]`
- `hello` becomes `["Ġh", "ello"]` (or further depending on available merges)
- Token ID 28120 is the vocab entry for `"Ġh"` (verified by checking the tokenizer.json merges)

**Output**: Sequence of token IDs — one ID per final BPE segment.

### Trace: Encoding a Single Space `" "`

**Input**: `" "` (one space character, ASCII 32).

**Pre-tokenization**:
```
pieces[0]: type = TOKEN_PIECE_SPACE, text = " ", len = 1
```

**Encoding in `sm2_tokenizer_encode`**:
```c
if (pieces[w].type == TOKEN_PIECE_SPACE) {
    int space_token = tok->byte_to_token[32];  // looks up byte_to_token[32]
    ids[n++] = space_token;
}
```

`byte_to_token[32]` was set during vocab loading to the vocab ID of the `Ġ` token (UTF-8 bytes `0xC4 0xA0`).

**Output**: `[ <vocab_ID_of_Ġ> ]` — a single token ID representing the space.

### Trace: Encoding `" hello"` (space + hello)

**Pre-tokenization**:
```
pieces[0]: type = TOKEN_PIECE_SPACE, text = " ", len = 1
pieces[1]: type = TOKEN_PIECE_WORD, text = "hello", len = 5
```

**Encoding**:
```
SPACE piece -> byte_to_token[32] -> Ġ token ID   [1 token]
hello piece -> bpe_encode_word("hello")           [N tokens via BPE]
```

**BPE for "hello"**: The base segments are `["h","e","l","l","o"]`. The merge table contains entries like `"Ġh"`, `"ell"`, `"llo"`, etc. The BPE algorithm greedily merges the lowest-ranked pairs:
- If `"Ġh"` is in the merges, and a leading space were present, it would merge.
- For `"hello"` with no leading space: `"he"`, `"el"`, `"ll"`, `"lo"` pairs are checked.
- Further merges combine `"ell"` into `"ello"`, producing `["Ġh", "ello"]` for `" hello"`.

**Output**: `[Ġ_token_ID, ...hello_BPE_token_IDs...]`

### Trace: Byte-Level Fallback (No Merges)

**Scenario**: `tok->num_merges == 0` or `tok->merges == NULL`.

**Base segmentation**: Each character byte is emitted directly:
```
"hello" -> [byte('h'), byte('e'), byte('l'), byte('l'), byte('o')]
        -> [104, 101, 108, 108, 111]
```

**Lookup**: `find_token_id_by_string` is not called. Raw byte values are used as token IDs.

**Output**: The raw byte values (which happen to be valid ASCII token IDs in SmolLM2's vocab for standard ASCII characters).

## Appendix: Key Data Structures

```c
typedef struct sm2_tokenizer {
    int vocab_size;               // 49152
    char** tokens;                // [49152] id -> UTF-8 string (id == array index)
    float* scores;                // not used in .sm2 format
    int* token_to_id;              // [49152] string -> id (always id-to-id mapping here)

    int num_merges;               // number of BPE merge rules
    char** merges;                // [num_merges] normalized merge strings (no spaces)

    uint8_t* vocab_data;          // raw bytes of tokenizer blob (not used after parse)
    size_t vocab_size_bytes;

    int byte_to_token[256];       // raw byte -> vocab token ID mapping
} sm2_tokenizer;
```

## Appendix: Critical Fixes Applied

1. **Merge normalization (space removal)**: The original tokenizer.json stores merges as `"token1 token2"`. The C implementation strips spaces in-place during loading, transforming them to `"token1token2"` for direct string comparison during BPE merging.

2. **`Ġ` byte-to-token mapping**: During vocab loading, when the token `Ġ` (UTF-8 `0xC4 0xA0`) is encountered, `byte_to_token[32]` (ASCII space) is set to that token's ID. This enables single-token encoding of spaces.

3. **In-place merge normalization**: The space-stripping loop modifies the merge strings in-place within the same buffer, avoiding extra allocation:
   ```c
   char* src = merge;
   char* dst = merge;
   while (*src) {
       if (*src != ' ') *dst++ = *src;
       src++;
   }
   *dst = '\0';
   ```
