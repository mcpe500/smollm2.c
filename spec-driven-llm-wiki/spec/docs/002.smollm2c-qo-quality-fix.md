# Spec 002: smollm2.c Quality Optimization (QO1-QO4)

## Task/Prompt

Fix smollm2.c to produce text quality comparable to Ollama/llama.cpp output. Current issue: model generates repetitive tokens (~"Ġso Ġwhat Ł" cycling) instead of coherent text.

## Tujuan

Membuat smollm2.c menghasilkan output yang comparable dengan Ollama. Target: kata "hello" → generate teks coherent seperti Ollama, bukan stuck dalam repetition loop.

## Root Cause Analysis

### Observed Behavior
- HF reference ALSO generates same repetition pattern (tokens 588/249/732 cycling)
- C engine produces: `! Lepathtake II II II II II...`
- Ollama produces coherent multi-sentence text

### Technical Analysis
1. **FFN computation**: Sequential loop-based matmul accumulates floating-point errors
2. **Attention pattern**: Sequential token-by-token processing vs Ollama's batch forward pass
3. **Softmax implementation**: Different numerically stable approaches
4. **Sampling**: Greedy (temperature=0) terlalu deterministic

### Key Insight
Repetition IS inherent to the model when:
- FFN activations converge to similar patterns across layers
- Attention can't properly differentiate token contexts
- Temperature=0 guarantees same output for same hidden state

## Fix Plan

### QO1: Fix FFN/SwiGLU Numerical Precision
- **File**: `src/sm2_context.c` (layer_forward)
- **Issue**: Sequential matmul accumulates FP errors
- **Fix**: Add FP32 accumulator with Kahan summation for accuracy

### QO2: Flash Attention Batch Prefill
- **File**: `src/attention/sm2_attn_flash_prefill.c`, `src/sm2_context.c`
- **Issue**: Sequential token-by-token processing
- **Fix**: Process all prompt tokens in one batch forward pass using flash attention kernel

### QO3: Check KV Cache Quantization
- **File**: `src/kv/`, `include/smollm2.h`
- **Issue**: KIVI-style quantization may introduce drift
- **Fix**: Verify KV cache uses F16 (no quantization) by default

### QO4: Tune Sampling Parameters
- **File**: `src/smollm2.c`, `src/sm2_sampling.c`
- **Issue**: Greedy sampling too deterministic
- **Fix**: Set default temperature=0.7, top_p=0.9 for more diverse output

## Code Changes

### QO1: FFN Numerical Precision
```
// Before: Sequential sum
float sum = 0.0f;
for (int j = 0; j < dim; j++) {
    sum += xb_out[j] * sm2_f16_to_float(gate_proj[gate_off + i * dim + j]);
}

// After: Kahan summation for numerical stability
float sum = 0.0f;
float c = 0.0f;
for (int j = 0; j < dim; j++) {
    float y = xb_out[j] * sm2_f16_to_float(gate_proj[gate_off + i * dim + j]) - c;
    float t = sum + y;
    c = (t - sum) - y;
    sum = t;
}
```

```
    // This sequential processing is the problem - replace with batch

// FIXED: Batch forward pass

for (int t = 0; t < n_tokens; t++) {

```
