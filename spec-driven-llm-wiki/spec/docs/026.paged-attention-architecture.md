# Paged Attention Implementation

## Overview

The paged attention mechanism in smollm2.c manages KV cache memory using fixed-size pages, avoiding external fragmentation and enabling efficient memory utilization for variable-length sequences.

## Page Configuration

| Parameter | Value | Description |
|-----------|-------|-------------|
| `SM2_KV_PAGE_TOKENS` | 16 | Tokens per page |
| Max Pages per Sequence | 256 | Maximum ~4K tokens per sequence |
| Max Sequences | Configurable | Limited by pool size |
| Head Dimension | 64 | Fixed for all SmolLM2 variants |

## Page Structure

```c
typedef struct {
    uint32_t id;           // Page identifier
    uint16_t used;         // Tokens in use (0-16)
    uint16_t refcount;     // Reference count (future: prefix sharing)
    uint32_t next_free;    // Free list link

    // Data pointers (supports multiple dtypes)
    uint8_t* k_data;       // Key data [layers * kv_heads * 16 * 64] bytes
    uint8_t* v_data;       // Value data (same layout)
    uint8_t* k_scale;      // Per-head quantization scale
    uint8_t* v_scale;      // Per-head quantization scale
} sm2_kv_page;
```

## Data Layout

Each page stores data for all layers and KV heads:

```
Page Layout:
┌─────────────────────────────────────────────────────────┐
│ Layer 0, KV Head 0: K[16, 64], V[16, 64]               │
│ Layer 0, KV Head 1: K[16, 64], V[16, 64]               │
│ ...                                                     │
│ Layer N, KV Head M: K[16, 64], V[16, 64]               │
└─────────────────────────────────────────────────────────┘

Offset calculation:
  data_offset = (layer * n_kv_heads + kv_head) * 16 * 64 + offset * 64
```

## Memory Calculations

### Per-Page Memory (135M, F16)

```
Bytes per kv_head per layer = 16 tokens * 64 dim * 2 (K+V) * 2 bytes (F16)
                             = 4096 bytes = 4 KB

Per page (30 layers, 3 KV heads):
  = 30 * 3 * 4 KB * 2 = 720 KB per page
```

### Per-Page Memory (135M, Q8)

```
Bytes per kv_head per layer = 16 * 64 * 2 * 1 = 2048 bytes = 2 KB

Per page:
  = 30 * 3 * 2 KB * 2 = 360 KB per page
```

### Pool Memory Examples

| Variant | Dtype | Tokens/Page | Max Pages | Pool Size |
|---------|-------|-------------|-----------|-----------|
| 135M | F16 | 16 | 64 | ~46 MB |
| 135M | Q8 | 16 | 64 | ~23 MB |
| 135M | Q4 | 16 | 64 | ~12 MB |
| 360M | F16 | 16 | 128 | ~295 MB |

## Page Table Management

```c
typedef struct {
    uint64_t seq_id;         // Sequence identifier
    int seq_len;             // Current sequence length
    int n_pages;             // Number of pages allocated
    uint32_t page_ids[256];  // Physical page IDs (max 256 pages)
} sm2_kv_table;
```

### Allocation Strategy

1. **Free Stack**: Pages are allocated from a free stack (LIFO)
2. **Lazy Allocation**: New pages allocated only when needed
3. **Page Fill Tracking**: `page->used` tracks tokens in current page

### Sequence Lifecycle

```
1. Init: table.n_pages = 0, seq_len = 0
2. Append token:
   - If current page has space: write to it
   - If current page full: allocate new page
3. Append complete: sequence pages tracked in table
4. Free: return all pages to free stack
```

## Memory Efficiency

### Benefits of Fixed-Size Pages

1. **No External Fragmentation**: All allocations are page-sized
2. **Fast Allocation**: O(1) via free stack pop
3. **Simple Coalescing**: No compaction needed
4. **Cache-Friendly Access**: Sequential writes within pages

### Fragmentation Analysis

```
Worst case (single sequence):
  Used: N * 16 tokens
  Allocated: ceil(N/16) * 16 tokens
  Waste: (16 - (N mod 16)) tokens per last page

Best case (multiple sequences):
  Average waste per sequence: ~8 tokens
  For 100 sequences: ~800 tokens wasted (negligible)
```

## Attention Computation

### Paged Attention Kernel (src/attention/sm2_attn_paged.c)

```c
void sm2_attn_paged(
    float* out,              // Output [n_heads, head_dim]
    const float* q,          // Query [n_heads, head_dim]
    sm2_kv_pool* pool,       // KV pool
    sm2_kv_table* table,    // Sequence page table
    int seq_len,            // Sequence length
    int n_heads,            // Query heads
    int n_kv_heads,         // KV heads
    int head_dim             // Head dimension
)
```

### Algorithm

1. Calculate number of pages: `n_pages = (seq_len + 15) / 16`
2. For each query head:
   - Iterate through pages, loading K,V from each
   - Compute attention scores per token
   - Apply online softmax (numerically stable)
   - Accumulate weighted values
3. Normalize output

### Online Softmax

```c
// Numerically stable online softmax
float max_s = -1e9f;
float l = 0.0f;
float acc[64] = {0};

// First pass: find max
for (int t = 0; t < len; t++) {
    float s = dot(q, k[t]) * scale;
    if (s > max_s) max_s = s;
}

// Second pass: compute exp and accumulate
for (int t = 0; t < len; t++) {
    scores[t] = expf(s - max_s);
    l += scores[t];
    for (int d = 0; d < head_dim; d++) {
        acc[d] += scores[t] * v[t][d];
    }
}

// Normalize
out[d] = acc[d] / l;
```

## Prefix Caching (Future)

The implementation includes `refcount` field for future prefix sharing:

```c
uint16_t refcount;  // Reference count for shared prefixes
```

This would allow:
- Sharing KV cache for common prefixes
- Copy-on-write for divergent sequences
- Memory savings for multi-turn conversations
