## Critical Bug: Magic Byte Mismatch

**Problem:** .sm2 file has magic `SM2C001\x01` (9 bytes) but C code expects `SM2C001` (8 bytes).

**Root cause:** In `tools/smollm2-convert.py`, line:
```python
MAGIC = b'SM2C001'  # This is actually 8 bytes + Python adds \x01 for null terminator?
```

Wait - `b'SM2C001'` is 7 bytes, not 8. The expected magic in C is `SM2C001` which is 7 bytes. But the file shows `SM2C001\x01` which is 8 bytes.

Let me verify: `SM2C001` = S,M,2,C,0,0,1 = 7 chars. `b'SM2C001'` in Python is also 7 bytes.

But the file shows 9 bytes: `b'SM2C001\x01'`. That's 8 bytes. Something is writing 9 bytes.

Actually looking at converter code:
```python
MAGIC = b'SM2C001'
f.write(MAGIC)  # writes 7 bytes
```

But the file has 9 bytes. Let me check the header writing more carefully...

Actually the issue might be that the header struct has:
- 8 bytes magic
- 4 bytes version
- etc

But the converter writes version as part of the same struct. Let me re-examine...

From converter:
```python
f.write(MAGIC)                                    # 8 bytes  (0-7)
f.write(struct.pack('<I', VERSION))              # 4 bytes  (8-11)
```

So MAGIC should be 8 bytes. But `b'SM2C001'` is only 7 bytes. The C code expects 8 bytes.

**Fix:** Change `MAGIC = b'SM2C001'` to `MAGIC = b'SM2C001\x00'` (8 bytes with null terminator).
